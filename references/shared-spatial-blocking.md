# 空间拓扑图（机位调度图）· 可执行规格（横切单源）

> 适用：听风线 / 虾镜线全部分镜流程——分镜开工前与拆镜过程中强制遵守。战斗段的空间信息经调度单「场景」字段传给外协模块（站位/轴线与所属场拓扑图一致，契约见 `shared-fight-dispatch.md`）。
> 性质：通用方法论，禁止出现任何具体项目数据；示例一律占位符（角色A / 角色B / 场景X）。
> 来源：从《空间拓扑图·制作原理详解》蒸馏（漫剧老李 V6.5 规范体系，已通用化改写）。

## 〇 与现有体系的关系及优先级（必读）

| 层 | 权威源 | 回答的问题 |
|---|---|---|
| 场景级布局 | scene-consistency「空间真理图」（文字版） | 每镜发生在**哪个场景**、锚点物在哪、门窗朝哪开、换景走哪条路 |
| 镜级空间调度 | **本规格「机位调度拓扑图」** | 站位在哪、面朝谁、**机位在哪侧**、轴线怎么立、怎么合法越轴 |

- **一致性**：拓扑图的锚点带必须与空间真理图锚点一致（两者从同一次空间梳理产出；真理图是布局权威源，拓扑图是调度垫图）。
- **冲突裁决序**：①安全与轴线铁律（同侧原则/合法越轴三手段）②本规格判定算法 ③其他规范的构图建议。
- **粒度铁律（★ 每场一张）**：一张拓扑图只画一场戏（同一连续空间）；多场戏挤一张图 = 轴线互相打架 = 错误。场景切分判定见 §五。
- **剧本层边界（★）**：剧本只产出"原文级空间证据/建议"（统一地点名 + 分区 + 道具锚点，见 `xiaju-script` 场景头铁律）；**锁定分区、机位、CAM、站位、180°轴线、越轴仍由空间真理图 + 本规格推导，剧本不得代劳**。剧本正文里的"分区 ›"仅是空间证据，非调度锁定值。
- **生图规范（★ 黑白简笔）**：对外生图/垫图一律用本规格 §十 的黑白简笔规范，替代旧彩色分区参考图版式；彩色/标签版不再产出。

## 一、它是什么

真人剧组开拍前副导演画的**俯视平面图**（floor plan / blocking diagram）的 AI 版：一张图画清"角色在哪、面朝谁、摄影机在哪、怎么动"，做成**简笔俯视示意图**作为垫图资产投喂视频模型。

一句话定义：**把三维拍摄现场压缩成 2D 俯视正投影，把"空间感"从模型最容易幻觉的自由变量，变成图上锁死的几何常量。**

## 二、解决什么问题

文字提示词天生缺坐标系。AI 视频三类高发空间事故，根因都是模型在自由脑补空间：

| 事故 | 表现 | 根因 |
|---|---|---|
| 跳轴（180° 违规） | 正反打切了一镜，角色左右突然互换 | 文字里"他走向左边"没有锚定"是谁的左边" |
| 方位无故反转 | 上一镜大帐在身后，下一镜跑到面前 | 逐镜独立生成，模型不共享空间记忆 |
| 空间穿模 | 角色走进墙里、兵器穿过身体 | 距离与遮挡关系靠脑补 |

拓扑图用一张图锁死三件事：锚点固定参照系、轴线约束机位、站位点标注距离与朝向。

## 三、投影原理：三维 → 2D 只留地面坐标

- **保留** X/Z 平面（地面坐标）：位置、距离、朝向、走位路径、机位方位；
- **丢弃** Y 轴（高度）：高度不画，交给文字里的"仰拍 N°/俯拍 N°/垂直拉升"表达——把高度画进图里，模型会当真往上看；
- **只画关系不画细节**：简笔几何（点、线、方块、虚线），无透视、无光影、无风格——模型从图里读的是**相对关系**；风格信息多了会串染成片画风（所以必须黑白简笔+至多一处红色轴线，与任何风格锚定不打架）。

## 四、五要素（制图顺序即依赖顺序）

### ① 空间锚点（先画不变的）
最先画场上**永远不动**的参照物：关墙、大帐、哨塔、门洞、立柱。它们是整张图的坐标系原点——后续所有站位、机位、走位都相对它们定义。
锚点选型标准：a) 跨镜稳定存在；b) 体积可辨识；c) 与戏剧动作相关（大帐会被掀飞，掀飞前后就是两个空间状态）。

### ② 站位点与朝向（再画会动的）
角色 = 一个点 + 一个朝向箭头。三铁律：
1. **移动轨迹闭环**：位移必须写 `起点 → 可见运动路径 → 终点`，上一镜在左的角色下一镜严禁凭空出现在右；
2. **绝对视角基准**：图上的左/右 = 观众看画面的左/右（不是角色自己的左右）；
3. **距离显式化**：关键间距直接标数（如"五十步""三里""十步"），这是文字提示词里空间尺度的唯一权威来源。

### ③ 180° 动作轴线（全图最值钱的一条线）
定义：两个角色视线/动作的连线，在俯视图上画一条虚线。
**原理**：机位在轴线同一侧时，人物在画面里的左右关系恒定（角色A恒在画面左）；机位一旦越到另一侧，画面左右瞬间镜像——观众会突然"认不出谁是谁"。AI 模型逐镜独立生成时最容易违反，所以必须画在图上锁死。

### ④ 机位编号 CAM1~4（一台一任务）

| 编码 | 任务 | 典型规格 |
|---|---|---|
| CAM1 主建立 | 立空间几何与左右朝向 | 30°~60° 斜角全景/中远景 |
| CAM2 双人交锋 | 承载对话与动作发起 | 平视中景（微仰/微俯） |
| CAM3 过肩反打 | 主观视点、压迫感与生理反应 | 过肩近景（允许 90° 侧） |
| CAM4 特写/顶视 | 微表情、要害接触、大招运镜 | ECU 微距 / 60° 俯拍 / 鸟瞰 |

分镜里每一镜的五要素（景别·视角角度·运镜·跟随目标）都必须能对应到图上某个 CAM 的几何位置——**文字负责这一镜拍什么，拓扑图负责所有东西在哪。**

### ⑤ 纵深边界（远景只做轮廓）
背景远景（如三里外敌军营火）在图上只画轮廓线/点线，并标注"禁入画展开细节"。作用：防止模型把背景元素写成主体、防止无意义细节诱发噪点与穿模。

## 五、场景切分判定（先定"一张图画什么"——每场一张的依据）

1. **单一连续空间**（同一地点、无切走）→ 一场一图；
2. **动作跨空间**（如 A 处打完走到 B 处死）→ 拆两张图 + 一个转场镜（遮挡过渡或中立镜），两图各自独立成轴；
3. **画中画/内外景同镜**（帐内看帐外）→ 外景为锚点带、内景画嵌套框，分别定轴，注明"嵌套关系"；
4. **判断口径**：以"**摄影机是否需要搬运**"为准——需要搬运就拆图。

每张拓扑图资产名带场标识（如 `空间拓扑图·场1`、`空间拓扑图·场2`），防止多图重名导致垫图/上传混乱。

## 六、角色数与轴线判定

| 情形 | 规则 |
|---|---|
| 双人（含 1v1 决斗） | 单主轴线 = 两人连线；全部机位同侧 |
| 三人以上群戏 | 以**核心冲突双方**定主轴线；其余角色按其站位标注"挂靠侧"（站在主轴哪半区），**任何人位移跨越主轴线 = 触发重立轴预案** |
| 多条冲突线并存（混战） | 每条冲突线一条轴线（虚线区分线型），机位取"所有激活轴线同侧的交集区"；无交集区时按镜头切换时刻轮换激活轴线，并在预案表登记 |
| 单人戏/无人空镜 | 无轴线；只画锚点+站位（或仅锚点），CAM 任放 |

## 七、三种合法越轴手段（越轴必须预先写在分镜里，禁止"生成出来再看"）

| 手段 | 原理 | 示例（占位符） |
|---|---|---|
| 机内过轴 | 单个镜头内摄影机跟随角色连续旋转穿过轴线 | 长跟拍环绕镜头 |
| 中立镜过渡 | 插入正面正对双人的中立镜或细节特写（Cutaway），再切反侧 | 对话中的信物特写 |
| 剧烈反弹重立轴 | 角色受重大物理打击翻滚位移后，空间重建，新轴线生效 | 角色A与角色B对撞后各退十几步 → 下段从角色B过肩开场完成换侧 |

## 八、CAM 分配算法（机械判定，按镜逐条跑）

```
对每个镜号依次判定（可叠加，最多标 2 个 CAM）：
1. 该场第一个镜                                → CAM1
2. 大景别立空间/时间跳跃后的第一个镜            → CAM1
3. 双人同框 + 有对白或对峙                     → CAM2
4. 单人主观视点/过肩/微表情反应                 → CAM3
5. ECU 微距 / 要害俯拍 / 大招收尾 / 鸟瞰        → CAM4
规则：CAM1 每场 ≥1 次且仅开头；连续 3 镜同 CAM 必须换（防呆板）；
     战斗段镜 4 起允许 CAM2↔CAM3 高频互换（机枪对招）。
```

## 九、输入 → 输出契约（四表，缺一即不完整）

**输入**（任一即可）：a) 剧本/小说章节原文；b) 已完成的分镜表（镜号+五要素）。

| # | 交付物 | 必含字段 |
|---|---|---|
| 1 | 空间坐标描述 | 场名、方位约定（上/下=什么）、全部固定锚点及相对方位、纵深边界、光源方位 |
| 2 | 站位表 | 每角色一行：`角色 \| 位置区（左/中/右×近景/中景/远端） \| 初始朝向 \| 位移链（起点→路径→终点，按剧情时序）` |
| 3 | 机位部署表 | 每机位一行：`CAM 编号 \| 图上位置 \| 任务类型 \| 承接镜号列表 \| 是否跨轴线（预案）` |
| 4 | 轴线与越轴预案表 | 主轴线两端、每条轴线的合法状态区间（哪几镜有效）、每个变更点：`镜号 \| 变更类型（机内过轴/中立镜过渡/剧烈反弹重立轴） \| 新轴线两端` |

**验收 checklist（全过才算交付）**：
□锚点全部为跨镜稳定物 □每角色有朝向箭头 □关键距离有数字 □所有镜号可归入某 CAM □所有 CAM 在其有效轴线的同侧 □每个越轴点有三手段之一标注 □远景边界有"禁入画"标注 □生图提示词为黑白简笔规范（无写实词、仅 CAM 编号可作文字） □每场一张（无多场挤一图）。

## 十、生图提示词规范（黑白简笔，★ 全线统一，替代旧彩色版）

拓扑图作为资产也要出图，提示词的关键是**把它定义为示意图而非场景**：

```text
16:9 横屏白底简笔示意图，手绘风格平面俯视机位调度图：以细黑线俯视平面绘制
[固定锚点带：关墙/大帐/哨塔…（方块示意）]；
[站位：左侧圆点+长枪小图标=主角方，右侧圆点+标识=对手方]；
两点间一条红色虚线直线 = 180° 动作轴线；
轴线同侧布置四个小相机图标 CAM1~CAM4，细弧线示意调度弧；
[下方纵深边界：远景要素点线]。
仅黑白灰 + 一处红色轴线虚线，线条干净简洁，无写实渲染、无人物、无照片质感
（blueprint sketch style），no photorealism, no text labels other than CAM1-CAM4 numbers。
```

三条硬规则：
1. **文字仅允许 CAM1~CAM4 与"主轴"二字**，其余信息全走图形语言（防模型乱码文字）；
2. **必须含 `blueprint sketch style` + `no photorealism`**（防画成鸟瞰场景图）；
3. **站位图标必须带可区分特征**（主角方长枪小图标/对手方冠饰小图标），防模型把两点画成无差别圆点。

> 注意：Midjourney 对 CAM 编号外的文字大概率乱码——本规范本就只允许 CAM 编号，正好安全。每场一张 = 每场一条独立提示词，写入该场的 space_map 字段，禁复用其他场。

**双语双产（★ 2026-09-06b）**：每场拓扑提示词同轮产出 `prompt`（英文·生图执行）+ `prompt_cn`（中文·理解审稿），对译逐段一一对应（锚点带/站位图标/主轴/CAM 布点/纵深边界/风格段）；图上文字白名单（CAM1~4 与「主轴」）在两版中同义。`prompt_cn` 缺失由 check-fidelity ⑫ 报缺。

## 十一、与时长控制的接口（跨文档咬合点）

- 轴线变更点必须**落在某个具体镜的时码上**，并在该镜标注变更类型（单源见 `references/shared-duration-control.md`）；
- 分镜表/段引用行的"空间拓扑图"位引用**该段所属场**的拓扑图资产名（末位固定）；
- 拓扑图修订（站位变了）必须回写分镜表的接续状态字段。**双向同步，禁止单边改。**

## 十三、Worked Example（占位符化，输出格式与深度基准）

**输入**：示例章节《对决》原文（约 7300 字），单一主战场。

**Step 1 场景切分**：主战场=大帐外空场（S01–S12，占 12 组）→ 主图；副场=哨塔（S13）、大帐内景（S14）、关城西墙（S15）→ 各出简版变体或仅出锚点行（单场戏降级）。判定：S13 角色C在哨塔、角色A在台下——两人隔台阶仰角，**无水平轴线冲突**，只画垂直关系（台阶方向），可并入主图备注或出极简版。

**Step 2 锚点带（上=关城方向）**：西关墙横带（上缘）→ 墙侧挂哨塔（左上小方块）、大帐（右上小方块）、暗道口（墙根圆点）；纵深边界=下方三里外敌军营火点线。

**Step 3 站位表（主图）**：

| 角色 | 位置区 | 初始朝向 | 位移链 |
|---|---|---|---|
| 角色A | 左区·中景距 | 朝右（向东） | S02 横兵定立 → S05 对撞后退十几步（向左位移）→ S11 半跪喘息 → S15 向哨塔行进（离场） |
| 角色B | 右区·中景距 | 朝左（向西） | S02 摘冠脱袍（原地）→ S05 对撞后退十几步（向右位移）→ S12 转身向右走出画面 |

关键距离：两人相距五十步（S02）→ 对撞后各退十几步（S05，间距不变≈仍五十步级）。

**Step 4 轴线与预案**：主轴=角色A-角色B连线（东西向红虚线）；CAM1~4 全部布置在轴线北侧。越轴预案两处：①S05 镜4（对撞位移）→ 剧烈反弹重立轴，新轴=两侧新站位连线；②S11 镜1 → 以 CAM3 角色B过肩开场，中立过渡完成换侧（此后角色A在画面右）。

**Step 5 机位部署表**：CAM1（左上斜角，主建立）→S01镜1/S02镜1；CAM2（中部正位，双人）→S02镜2/S03 对招/S07 正反打；CAM3（左中过肩）→S04镜2/S07镜3/S11镜1；CAM4（右上俯拍/特写）→S03镜2 兵器特写/S04镜1 足部俯拍/S09镜5 碎裂特写。自查：CAM1 仅开头 ✅、无连续 3 镜同 CAM ✅。

**输出**：空间坐标描述 + 站位表 + 机位表 + 预案表（四张表）+ 每场一条黑白简笔生图提示词。

## 十四、常见错误清单（生成前自查）

1. 把拓扑图画成写实鸟瞰场景图（模型会读入画风）；
2. 图上写满文字标注（诱发成片乱码文字）——只允许 CAM 编号；
3. 左右基准混乱（一会儿观众视角一会儿角色视角）；
4. 只画轴线不写越轴预案（生成时照样乱穿）；
5. 锚点用了"会动的东西"（大帐烧没了还当原点）；
6. 高度信息画进图里（画了立面，模型当真往上看）；
7. **多场戏挤一张图（轴线互相打架）——每场一张铁律**；
8. 拓扑图锚点与空间真理图锚点不一致（两图脱节）；
9. **首帧不可重建**（写了动作却没写清开场状态，模型自由脑补起点）——见 §十五。

## 十五、首帧可重建纪律（★ 2026-09-05 新增）

> 来源：从「影词精磨」First-Frame Reconstructable 规则蒸馏，通用化改写。
> 分工：本规范**管空间几何与机位**（拓扑图、轴线、CAM）；首帧的**表演内容**（表情/呼吸/持物质感）归 `shared-performance-realism.md`；首帧的**台词与声线状态**归 `shared-dialogue-performance.md`。三者共同构成"首帧可重建"，互不替代。

**核心判断**：首帧是模型唯一被强制对齐的锚点。首帧模糊 = 把开场状态交给模型自由脑补 = 后续所有连续性的起点都不可靠。**每镜的最终提示词必须能让人在脑中重建出开场那一帧**，而不是只描述"接下来会发生什么"。

### 15.1 有人物的首帧（必写六项）

| 项 | 内容 |
|---|---|
| **主体** | 谁/什么在画面里（含身份锚点：年龄感、服装、发型、当前损伤或湿尘状态） |
| **姿态** | 站/坐/蹲/倚靠，重心在哪，四肢大致位置 |
| **屏幕位置与纵深** | 画面左/中/右、前景/中景/背景 |
| **朝向** | 面朝画面哪一侧/朝向谁（与轴线、视线匹配同源） |
| **视线** | 看向何处（对方/镜头/画外某点/下垂） |
| **持物/接触** | 哪只手持何物、握持或支撑点在哪、与何物接触（与持物手连续同律） |

### 15.2 空镜/物件主导的首帧（必写六项）

| 项 | 内容 |
|---|---|
| **地点布局** | 什么空间，出入口在哪（与空间真理图锚点一致） |
| **前/中/后景** | 三层各有什么，纵深关系 |
| **关键物件状态** | 物件在哪、什么状态（开/关/满/空/破损/倾斜） |
| **天气与环境运动** | 雨/雪/风/尘埃/光斑是否在动、往哪动 |
| **主光源** | 光源是什么、从哪个方向来（与 quality-gate §三 光源动机同律） |
| **景别与机轴** | 中文九档景别（对照表见 `shared-performance-realism.md` 通用纪律 §4）+ 机位高度与轴向 |

### 15.3 强制场景

以下场景**必须**显式写出首帧状态，不得省略：

- 一镜到底段（起点即全段基准）；
- 参考图/首尾帧工作流（首帧图与提示词必须可互相对照）；
- 对白段（说话者起始姿态与视线决定后续正反打是否成立）；
- 动作段（起始站位与持械手决定攻防可读性）；
- 情绪特写（起始表情是整条情绪波的零点）。

### 15.4 写法示例（占位符）

```text
首帧：中近景，机位在轴线左侧 CAM2。角色A坐于餐桌右侧，身体略向桌心前倾，重心压在左肘；面朝画面左，视线落在对面的角色B身上；右手拇指与食指扶住杯壁，杯身稳定在桌面原位。背景为半明客厅，主光源来自画面左上方的暖色吊灯。
```

### 15.5 自检

- [ ] 这一镜的开场状态能否被独立重建（不需要看上一镜或猜）？
- [ ] 有人物镜：姿态/位置/朝向/视线/持物六项齐全？
- [ ] 空镜：布局/前中后景/物件状态/环境运动/光源/景别机轴六项齐全？
- [ ] 首帧的空间事实与本节拓扑图、空间真理图一致（无三处打架）？
- [ ] 首帧的表演内容与 `shared-performance-realism.md` 一致（非"贴情绪标签"）？

## 十六、四层空间权威表（★ 2026-09-10 并存新增；不改本文件既有章节）

> 由 manju-laoli V6.5 审查 + 三张实测生图（拓扑简笔 / 真理图 v2 / 空间基准图）沉淀。只定职责边界，**不改动 §一~§十五 与任何既有产物**。

| 问题 | 权威 | 形态 | 进模型？ | 决定什么 | 病去哪查 |
|---|---|---|---|---|---|
| **有没有依据？** | 空间真理图（§五每场切分依赖的锚点/行号层） | 文字＋`[Lxx]`/`[INFER]`，唯一写入点 `space-truth.json` | **不进**（进门禁） | 锚点出处、四面朝向、跨场景连通、换景判定 | 窗开错墙／凭空多锚点／换景判错 |
| **长什么样、东西在哪？** | 空间基准图 layout（虾塘 `scene-assets.md` §A2） | 带风格 3/4 轴测 16:9，垫图 `role=layout` | 进，当参考图 | 跨集跨机位的一致性（布局＋外观） | 院子每集长得不一样／换机位灶跑了 |
| **能不能这么拍？** | 机位调度拓扑图（本规范 §四~§八、§十） | 无风格黑白简笔，每场一张 | 进，当几何垫图 | 左右归属、轴线同侧、朝向、位移合法性、可用空间 | 跳轴／背对背／上一镜左下一镜右 |
| 定基调（可选） | §A 全景鸟瞰图等既有氛围图 | 各自原有版式 | 进 | 第一眼质感；**不承担一致性** | —— |

**三条裁决**（与既有章节冲突时按此裁决，裁决不得改图将就）：

1. **执行靠图，校验靠文字**：真理图不出图（实测：锚点按清单竖排则局部罗盘沦为装饰，空间增益为零；出图必与 layout 图重叠成双写漂移）。它保持文字才能被 `check-space-truth.py` 机械比对。
2. **风格话语权归带风格的图（layout），几何话语权归无风格的图（拓扑）**：拓扑必须无风格——它越不像一张画，越不会被当成一张画来学。两类图同喂不冲突，因为一个放弃画风、一个只交几何。
3. **锚点单源派生**：layout 与拓扑的锚点段一律由 `modules/scene-consistency/scripts/gen-layout-prompt.py --topology-band` 从 `space-truth.json` 逐字取，**手改视为污染**；改布局先改 json，再重生两类图。

**拓扑图 §十 实测补丁三条**（尚未回写进 §十正文，先挂此处，待 §十 修订时并入）：① 红色轴线一律无箭头，朝向箭头单独附着于点（实测轴线带箭头会吞掉站位朝向）；② 图上文字白名单仅 CAM1~CAM4，角色一律可区分小图标、禁人名（实测写角色名必乱码）；③ 副轴（重立之轴）用灰虚线，红色全场唯一。
