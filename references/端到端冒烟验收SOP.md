# 端到端冒烟验收 SOP（dry-run · ★ 2026-09-03 P2-5）

> 目的：流水线结构/契约/脚本变更后（如版本升级、模块集成），用**一个测试剧本**把 7 步最短路径完整 dry-run 一遍，在"进真实项目"前暴露断链。轻量文档流程，不是自动测试框架。

## 1. 测试剧本要求

- 自备一份 2000-5000 字的**虚构测试剧本**（占位世界观：角色用 角色A/角色B/角色C，场景用 场景X/场景Y，含 1 个血缘/状态关系 + 1 个反复出现的道具 + 1 个战斗段——覆盖全部新增机制的触发条件）；
- 剧本放在**临时项目目录**（用完可整目录删除），禁止使用真实项目。

## 2. Dry-run 步骤与核对点（对照 §0.5 七步）

| 步 | 模块 | 核对点（本步产物必须存在且合规） |
|---|---|---|
| 1-2 | 项目初始化 + 虾料 | `pipeline-state.json` 有 `skill_version`；`production_facts` 六项齐 + 四级标注；`outputs/scene-chain.md` 存在且命名规范 |
| 3 | 虾格 | `emotion_curve` 节点 8-16 个、呼吸区有文本依据；写实线 `p1_cinematic_baseline.enabled` 判定正确；三件套 + 曲线一起拍板；FS 库生成 |
| 4 | 虾塘 | 依赖登记（血缘关系角色有 dependencies）；写下游提示词前上游已定稿；check-assets.py 通过；道具锚点进词 |
| 5-8 | 分镜线（选一条跑通即可，另一条抽验输入契约） | 拆镜前读共享规范（基调吸收/生产事实）；听风：tingfeng.json 含 `full_text`、**check-fidelity.py 退出码 0**；虾镜：过 scene-consistency 三产物 |

## 3. 冒烟通过标准

1. 每步核对点全部存在（缺 = 断链，修复后重跑该步）；
2. 全部脚本（check-assets / check-scenes / check-fidelity）按预期退出；
3. grep 污染（旧项目关键词）为零；
4. 临时项目目录用后删除，skill 与模板零残留。

## 4. 何时必须跑

- VERSION 主版本/次版本递增后；
- 新模块集成、契约字段变更、脚本增删后；
- 更换 AI 工具/环境跑虾系之前（一次性验证）。
