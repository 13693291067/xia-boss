# 虾镜（novel 风格分镜工作台）

> ★ 2026-08-21 重构：虾镜从「DramaClaw 产品级还原（5 区流程/调度图/画面标注/合成导出）」改为 **novel 风格分镜工作台**——集数层保留，集内 Tab 为 **分镜脚本 / 故事板 / 制作** 三个（原产品级版已弃用删除）。

## 0. 定位（一句话）

**虾镜 = 集数 × [分镜脚本 | 故事板 | 制作] 的分镜工作台**：集数层保留流水线概念；集内通过「分镜脚本」列表统一编辑分镜（6 字段简版）→「故事板」生成单张简约线条故事板稿（6/9 格）→「制作」面板逐镜产出首帧/尾帧/视频（11 字段 + 产物区）。

## 0.5 与旧版/原版的关系

- 本 skill 接管「虾镜」在虾系流水线中的位置（xia-boss / xia_Director 调用本 skill）。
- 版本：本 skill 为虾镜唯一实现（原 DramaClaw 产品级版：5 区流程/调度图/画面标注/合成导出已于 2026-08-21 弃用删除，不再保留）。
- 保留自虾系的底层方法论（见 §6 执行纪律）：首帧 5 段式、Seedance STYLE LOCK、草图中文模板、锚点预可视化、全局色调总表、音频双轨、画面节奏切分、场景禁人物铁律、关键场景例外、身份图两图制、check-assets 校验。

## 2. Tab1【分镜脚本】分镜列表（★ 2026-08-22 重构：大纲 7 列 · 分镜大纲为内容源）

> ★ **流程（2026-08-22 用户拍板，推翻旧两步法）**：完整分镜脚本（storyboard-method.md 产出 11 字段）→ **分镜大纲生成器（`references/outline-generator.md`）产出大纲** → 大纲逐镜字段（画面要点/台词声音/叙事功能）**写回 shots.json 的 `outline_visual / outline_dialogue_sound / outline_function`** → Tab1 分镜列表显示大纲 7 列；制作页（Tab3）仍用完整 11 字段。
> ★ **做分镜脚本内容（拆镜/定时长/定景别构图/写 11 字段）时，加载 `references/storyboard-method.md`**（分镜方法论总纲：设计原则/镜头时长规范/镜头语言库/组合要求/色彩光影/11 字段）。
> ★ **产出分镜大纲时，加载 `references/outline-generator.md`**（五步流程：时长核算逐镜求和/段落分组/逐镜压缩/亮点标注/连续性红线）。

### 2.1 列表结构（7 列 · 分镜大纲逐镜表）

| 镜号 | 秒 | 景别 | 运镜 | 画面要点 | 台词/声音 | 叙事功能 |
|------|----|------|------|----------|----------|----------|

- **镜号**：唯一标识，不可编辑（由拖动/添加自动重排）。
- **秒**：镜头时长（逐镜求和 = 集总时长，禁止估算）。
- **景别**：远景/中景/近景/特写等（与制作页"景别"同源）。
- **运镜**：压缩为"动词+方向+速度档"（固定/缓推/缓拉/横移/跟移/甩镜/正反打/焦点转移/手持2%）。
- **画面要点**：≤30 字（人物+动作+关键道具+空间关系），大纲压缩版（`outline_visual`）。
- **台词/声音**：关键台词（金句/信息句/反转句）+ OS 核心一句，环境声省略（`outline_dialogue_sound`）；**台词=人声，不含音效细节**。
- **叙事功能**：2-8 字动宾短语（建立空间/埋设伏笔/爆点揭底/反应镜头/情感落点…）（`outline_function`）。
- **数据源**：shots.json 每镜 `outline_visual / outline_dialogue_sound / outline_function`（大纲生成器写回）；无大纲字段时回退完整字段（visual / dialogue+sound / narrative）。

### 2.2 编辑机制（★ 用户 2026-08-21 拍板；2026-08-22 副本分离重构）

1. **单元格编辑**：除镜号外 6 列（秒/景别/运镜/画面要点/台词声音/叙事功能）支持行内编辑；保存时写**编辑稿**（原始保留）。
2. **拖动重排（★ 2026-08-22 插入式 + 确认弹窗）**：拖动中目标行**高亮**（`tr.xj-drag-target`，表明插入该行后）；松开后 `confirm` 弹窗「是否将镜 X 插入镜 Y 后？」→ 确认才执行插入式重排（镜 X 抽出 → 插入镜 Y 后面 → 全镜号重排 `padStart(2,"0")`）；取消恢复原状。
3. **添加分镜**：底部「＋ 添加分镜」→ 末尾插入新行（镜号续号），新行数据为空模板。
4. **删除分镜**：**硬删**该行（从编辑稿 shots 数组移除）。
5. **重置分镜（行级）**：修改过的分镜显示「↺ 重置」→ 恢复 `original_shot`（编辑前的原始数据）。
6. **重置分镜（整集，★ 2026-08-22 新增）**：分镜脚本页标题行「↺ 重置分镜」按钮 → confirm 警示 → 删除本集**编辑稿**（`edited_shots` + `shots.edited.json`）→ 自动回到原始定稿；清除所有编辑/添加/删除/拖动。
7. **★ 编辑副本分离（2026-08-22 用户拍板，核心架构）**：**原始分镜永不修改**——原始定稿 `outputs/xiajing/ep{NNN}/shots.json` + SQLite `ep.shots` 只由 build/数据脚本写入；页面编辑（save/delete/add/reorder）只操作 `ep.edited_shots`（首次编辑时从原始深拷贝），写回 `shots.edited.json`；前端 `xjShots(ep)` 优先读 `edited_shots`，无编辑稿则读 `shots`；行级副本机制 `is_edited` + `original_shot` 在编辑稿内生效。

## 3. Tab2【故事板】简约线条故事板生成器（6/9 格 · 独立文件调度）

### 3.1 定位

把当前集的分镜（勾选，**一格对应一个分镜 beat**）生成**单张故事板分镜稿提示词**（平面简约线条简笔画风格），供用户外部生图。**完整模板见独立文件 `references/storyboard-prompt.md`，做故事板提示词时加载**（来源：《简约线条故事板提示词Skill版》改造，2026-08-21 用户拍板 6/9 格）。

### 3.2 输入与校验（6/9 格）

- 输入：勾选分镜（N ≥ 1）；**单张只取 ≤9 个 beat——N > 9 提示"超过 9 镜，请分批勾选（每批 ≤9）"**。
- 每格数据映射：镜头设计（景别/机位/角度/焦段/景深/运镜，**中英双语**）+ 画面内容（动作/剧情/人物/场景/道具，转写为客观可视描述）。

### 3.3 布局规则（★ 6/9 格，一格一个 beat，用户拍板）

- **单张故事板固定 9 格（3×3）或 6 格（3×2），一格对应一个分镜（beat）**；分镜不足版式格数时多余画格留全白。
- **拆分规则（优先 9 格，其次 6 格）**：N ≤ 6 → 6 格（3×2）；7 ≤ N ≤ 9 → 9 格（3×3）；N > 9 → 拆多张（每张 9 格，末张按"余数 1~6→6 格、7~8→9 格"降级）——前端单张交互取 ≤9 个 beat。
- 每格严格 16:9，多余格子留全白、不绘制任何内容。

### 3.4 模板与约束

- 完整模板（前置准备语/收料校验/字段映射/双语规范/页眉/版面/美术风格/参考素材/连贯性/逐格写法/硬约束）见 `references/storyboard-prompt.md`。
- 逐格写法：`P 序号 / {镜头标签} / {动作段落名}`：① 镜头设计（景别/机位/角度/焦段/景深/运镜 中英双语）② 画面内容（客观可视描述）。

### 3.5 输出与存储

- 输出：故事板提示词文本（一键复制）。
- 存储：用户生成的故事板图放 `assets/ep{NNN}/storyboards/`（前端展示缩略图）；批量生成按集存 `ep.storyboard_image`。

## 4. Tab3【制作】选中镜头的制作面板

### 4.1 布局（左右等分两列）

- **顶部信息条**：镜号 / 时长 / 所属场景 / 出场人物；◀ 上一镜 ｜ 下一镜 ▶ 导航。
- **左列（11 字段分镜完整内容）**：
  1. 所属场景 2. 出场人物 3. 景别 4. 摄影机参数 5. 构图方式 6. 画面内容 7. 人物动作与表演 8. 运镜方式 9. **台词** 10. **声音** 11. 镜头叙事作用
  - ★ **台词与声音必须分开两个字段（★ 用户 2026-08-21 拍板）**：台词=对白/旁白（人声）；声音=环境/动作音效（如"门轴嘎吱、喊杀声、心跳声"）。**分镜脚本列表 6 字段里的"台词"就是台词（人声），不含声音**。提示词中声音不进画面（三层剥离，见 §6 纪律 8）。
  - ★ **11 字段编辑（★ 2026-08-22 用户拍板：编辑从分镜脚本页迁移至此）**：标题行「✏️ 编辑」→ 全部字段变可编辑（**含「时长（秒）」，共 12 字段**），按钮变【💾 保存】【✖ 取消】；保存走副本机制（is_edited/original_shot → /shots/save）；翻镜自动退出编辑态。
  - ★ **所属场景显示场景资产名**（scene_name || scene_map[scene_tag] || scene_tag，不显示 SC 编号）。
- **右列（4 组产物区）**：
  - **📌 画面标注组（★ 2026-08-22 新增，放首帧上方）**：标注图（Canvas 工具，无历史）——缩略图 + 【📌 标注】；底图规则：有标注图→加载它 → 无→有首帧图→首帧 → 无→**所属场景正面资产（views.正面）→ 场景主图** → 无则手动「🎬选择场景」；工具：文字/编号/圆/矩形/画笔 + 选择拖动缩放 + 缩放/空格平移 + 全屏 + 撤回；保存写 `shot.annotated_image`（/save-annotation，文件 `assets/ep{NNN}/annotation/shot{N}-annotated-{ts}.png` 清理旧文件）。
  - **首帧组**：首帧提示词 textarea + 首帧图片（缩略图 + 上传 / ✨生成 / 历史）。
  - **尾帧组**：尾帧提示词 textarea + 尾帧图片（缩略图 + 上传 / ✨生成 / 历史）。
  - **视频组**：视频提示词 textarea + 视频（播放器 + 上传 / ✨生成）。
  - 每组提示词配 💾保存提示词 / ✨生成 / 📋复制。
  - ★ **生图自动引用画面标注（2026-08-22 用户拍板）**：首帧/尾帧生成自动垫参考图，**顺序 = 角色资产图1..N → 场景图N+1 → 画面标注图最后**（有标注才引用）。

### 4.2 数据字段

见 §5 数据契约（shots[]）。6 字段（列表）与 11 字段（制作页）为**同一数据源**：列表取 6 列，制作页展示全部。

## 5. 数据契约（shots[]）

```json
{
  "shot_number": "001", "duration": 6, "uid": "a1b2c3d4e5f6",
  "shot_type": "远景", "visual": "...", "dialogue": "...", "composition": "...",
  "scene_tag": "SC-01", "scene_name": "高档西餐厅", "characters": "无（空镜）", "camera": "...",
  "action": "...", "movement": "...", "sound": "...", "narrative": "...",
  "firstframe_prompt": "...", "firstframe_image": "...",
  "tailframe_prompt": "...", "tailframe_image": "...",
  "video_prompt": "...", "video": "...",
  "annotated_image": "...",
  "is_edited": false, "original_shot": null
}
```

- **字段说明**：
  - 列表 6 列：`shot_number / duration / shot_type / visual / dialogue / composition`
  - 制作页 11 字段：`scene_tag / characters / shot_type / camera / composition / visual / action / movement / dialogue / sound / narrative`
  - 制作产物：`firstframe_prompt/image / tailframe_prompt/image / video_prompt/video`
  - **画面标注（★ 2026-08-22）**：`annotated_image`（Canvas 标注图，资产 `assets/ep{NNN}/annotation/shot{N}-annotated-*.png`，保存清理旧文件**无历史**；build 反推最新一张）
  - 副本机制：`is_edited`（是否被编辑过）+ `original_shot`（编辑前原始数据，重置依据）
  - **`uid`（★ 2026-08-22）**：每镜稳定唯一标识（uuid4 hex[:12]）——拖动重排按 uid 传顺序（镜号是位置标识会重编号），reorder 后端 uid 优先匹配、镜号兜底。
  - **`scene_name`（★ 2026-08-22）**：SC 编号 → 场景资产名（build 从 ep.scene_map 解析），制作页显示/生图场景引用用；旧编辑稿缺该字段 → build 补。
  - **镜级场景命名（★ 与剧本"统一地点名+分区"对齐）**：`scene_name` 允许写成"母版名 › 分区"（如 `新娘更衣室 › 化妆桌区`），**只要含虾塘场景母版全名作前缀**即命中——首帧/尾帧生图垫场景图靠 `sn.includes(资产全名)` 子串匹配（见 `xiajing.js`），丢了前缀 = 静默不垫图。
  - **分区不新增母版（★ 守主键链）**：`ep.scene_map` 的值、虾塘 registry `scenes[].name` 一律用**纯地点母版名**（如 `新娘更衣室`），分区只是镜级描述后缀；给分区单立场景资产会使 build 校验 `scene_name 未映射镜头 = 0` 失败且无图。
- **ep 级字段（★ 2026-08-22）**：`ep.edited_shots`（页面编辑稿，无则 null，优先于 `ep.shots` 被前端读取）+ `ep.scene_map`（SC编号→场景资产名，**必须覆盖该集全部 SC**，无映射=缺项退回，见 scene-assets.md §D4）。
- **数据源（★ 2026-08-22 更新）**：原始定稿 `outputs/xiajing/ep{NNN}/shots.json`（兼容读取原 beats.json）+ 页面编辑稿 `outputs/xiajing/ep{NNN}/shots.edited.json`；build-data-js.py 组装 `xiajing.episodes[].shots[]`（原始）+ `edited_shots`（编辑稿，存在才读）+ `scene_map`；**原始 shots.json 永不被页面编辑覆盖**。
- **角色 aliases（★ 2026-08-22）**：虾塘 characters 带 `aliases`（资产名/简称匹配），首帧/尾帧自动引用角色资产时按 资产名或别名 匹配镜头文本。

## 6. 执行纪律（底层方法论 · 沿用虾系）

1. **首帧/尾帧提示词 = 顶部资产引用行 + 5 段式（★ 独立文件调度）**：`firstframe_prompt`/`tailframe_prompt` = 顶部资产引用行（角色A=图1，示例大殿=图2）+ 5 段式正文（①风格与质感 ②镜头 ③色彩 ④画面内容 ⑤限制）。**完整规范见 `references/prompt-5section.md`，生成首帧/尾帧提示词时加载**（英文纯净；首帧=动作开始前状态，尾帧=动作终点/反应状态；不重复人物外貌设定，只写姓名）。
1b. **★ 生图自动注入资产引用（2026-08-22 用户拍板，制作页首帧/尾帧生成自动执行）**：打开生成弹窗时自动——①提示词开头插入「角色名=图1 场景名=图2」+换行；②自动垫角色/场景资产图参考图（图号=参考图顺序）。规则：角色按镜头文本匹配（资产名或别名，见 character-assets.md §9），取该镜对应身份**四视图**（pickIdentityByText 四级匹配：全名→短名→2+字子串→兜底第一身份；无四视图降级定妆照/主图）；场景取 scene_name（scene_map 解析）；**取数必须编辑稿优先**（`edited_shots || shots`，与页面显示一致，防编辑稿改过的出场人物漏引）。
2. **video_prompt = 按「生视频模型」设置路由（★ 双模型调度，独立文件调度）**：每个镜头独立输出一段可复制的生视频提示词。**页面「生视频模型」设置决定用哪个模板**：
   - **= Seedance 2.0**：用 STYLE LOCK 导演模板 = 顶部资产引用行 + 【STYLE LOCK 风格锁】+【分镜画面 Shots】+【声音设计】+【关键约束】。完整模板见 `references/seedance-stylock.md`（中英术语并写/HEX 色值/一人一图锚定/硬切 only/不越轴/跨镜连续/real-time speed）。

14. **拆镜七步法（★ 2026-08-22 用户拍板，最高纪律，拆镜必须按序执行、一步不可跳）**：

    - **①.5 空间真理图（★ 2026-08-31 挂载，scene-consistency 第 1 步，检查点 A 必做，防"场景归属错乱"）**：通读本章剧本逐段提取空间描写（行号+原句）→ 原文沉默的空间按动作语义推断并标注依据 → 产出《本集空间拓扑图》（场景布局/角色初始位置/空间关系）→ 与场景资产库比对，缺的进「补建清单」（append 尾部不动旧图号）→ **空间真理图 + 补建清单随检查点 A 一并给用户确认**。铁律：原文有空间词必引用原句；原文沉默禁止默认填第一个场景；scene 只能选自资产库，缺资产先补建、禁近似场景硬压。完整流程见 scene-consistency 子 skill（`xia-boss/modules/scene-consistency/`）。
    - ② 建 **FS 固定风格库**（按场景类型编号，每镜首帧标注 FS）；
    - ③ 定**轴线约定**（谁左谁右、不越轴 180°）+ **表演基调 Performance Lock**（每角色一句表演总纲）；
    - **★ 最优性三问（2026-08-22 用户拍板，最高纪律，设计决策级闸门——与 4 问是两层）**：4 问（镜头级）保证"每镜合理"，本三问（决策级）保证"每个设计选择最好"，作用于**设计决策点**（角色登场方式/时间跨度/奇观呈现/镜头拆合/悬念留白）：①这个设计对观众的效果是什么？②**主动列出 2-3 个候选方案，比较哪个更有效**（禁拍脑袋选"稳妥的普通选项"）；③全剧视角下是否最优（会不会破坏未来伏笔/呼应）？例：未揭晓角色"露脸 vs 剪影留白"、结尾"深夜 vs 晨光收束"、摊牌段"合并 vs 拆满逐镜砸"。**三问下沉到每段落尾部**：每个段落的「尾巴设计」（喜剧余韵 / 劝诫台词 / 悬念留白）同样过三问——要不要做、做哪个效果最好，**禁直接砍掉剧本里已有的细节**。

    - **任何一步缺失 = 交付不完整，退回补齐**；完整度对照锚定示例 `references/example-shotlist-36.md`（36 镜完整方法论产物，脱敏版）。
    - **拆镜两检查点（★ 最高纪律）**：**检查点 A** = ⓪~④（全剧上下文确认 + 编号表 + **①.5 空间真理图 + 场景补建清单** + FS 库 + 轴线/表演基调 + 拆镜方案 **+ 反应/心理镜安排表 + 本章亮点设计清单**）→ **先交用户确认**；确认后 **检查点 B** = ⑤~⑦（11 字段 + 提示词全量 + 质检）。基础设施缺失必须在 A 暴露，不得带残缺一路做完。

    - **整段抽出铁律（虾镜落位 = 特殊镜行）**：战斗段**不做拆镜七步法 ⑤~⑦ 逐镜设计**——每个战斗子段（≤15s）在 shots[] 中落位为**一个特殊镜行**：`route:"武戏"` 标记 + `visual` 写「战斗段：<子段概要>，外协提示词见本镜视频提示词」+ 正常镜号与时长（=子段时长）；**无 11 字段逐镜拆分、无首帧/尾帧提示词、无 H3 双产**；相邻文戏镜不得夹带打斗动作描述；战斗段直接后继镜（余韵/收束）仍按文戏流程走（简化门禁：状态连续 + 环境因果锚定 + 接触与结果不可省略）；
    - **调度与回流（检查点 A 确认后执行）**：按单源协议组装八字段【打戏调度单】（segment_id / 群战人数结构 / 角色A·B ← 虾塘角色卡「战斗语言」/ 场景 ← 虾塘 scene-assets / 视觉风格 ← 虾格 creation-direction.json 原样搬运禁改写 / 战斗节奏 / 结局 / 特殊要求）→ 用户确认调度单 → Read `../seedance-combat-prompt/SKILL.md` 按其工作流生成 15s 提示词 → 用户确认产出 → **整段回流**：回填对应特殊镜行的 `video_prompt` = seedance 提示词全文（自足，无引用行/STYLE/执行约束外壳）、**负面四禁**（武器形态漂移/动作接触失真/力量反馈缺失/慢动作滥用）并入该镜负面提示词行；>15s 战斗段拆多张单（一个子段 = 一个特殊镜行），后单「段间衔接」声明前单末状态；
    - **虾镜线验收（暂无机械门禁，人工逐项核对，结果写入交付简报）**：① `ep.battle_segments` 已登记且镜号区间与特殊镜行对得上；② 战斗子段均为特殊镜行（route=武戏、无逐镜 11 字段/无首尾帧提示词）且相邻文戏镜未夹带打斗动作；③ 负面四禁在该镜负面提示词行内；④ 高危词已过 `../../references/shared-compliance-lexicon.md` 转译；⑤ >15s 多单各占一镜且段间衔接状态连续。
