# 听风分镜模板（storyboard-cinematic 输出格式）

> 依据：`听风剧本电影化分镜导演_原文.md`（方法论权威源）。本模板只固化**输出格式**，规则一律以原文为准。
> 示例全用占位符（角色A / 场景X / 红色物件），禁止项目数据。

## 〇、衔接决策（★ 非首集强制，Stage 0 产物；格式模板）

> 判定标准见 SKILL.md §1.7。示例全占位符。

```
〇、与前集的衔接决策

1. 源文本重演识别：本集开头（P<起>）与前集结尾（P<止>）是否存在同一事件的重复叙述？
   → 识别结果：<有/无>；<有：描述重演范围>
2. 取舍方案：本集承接点 = 前集第 <N> 段出段钩子「<钩子原文>」；重演内容由本集 <替代演绎/跳过>；前集 <不动/需回改>
3. 剪辑：本集首帧 = 前集第 <N> 段末帧
```

**形象匹配检查表**（资产盘点查二；资产存在性查 db 快照，不查导出文件）：

```
| 角色 | 本集原文描写要点（章节+原句） | 资产身份（chapter_range）形象要点 | 判定 | 处理 |
|---|---|---|---|---|
| <角色X> | <chNNN「原句摘录」> | <身份名（chNNN-chNNN）：年龄/体型/服装> | ✅匹配 / ⚠️冲突 | <无 / 加新身份·修正·报用户> |
```

## 一、分段表（原文 Stage 1 产物）

| Segment | Route | Duration | Script Range | Core Action | Exit Hook |
|---|---|---|---|---|---|
| S01 | 文戏 | 10s | 第1段（开场） | 角色A进入桥洞环境 | 手伸向红色物件 |
| S02 | 收束 | 12s | 第2段 | 红色物件被拿起 | 火光映在瞳孔 |
| … | | | | |

- 段数估算 = 总时长 / 12s；段边界落在自然停顿（场景切换/情绪转折/动作峰值）。
- 动态时长：动作段 8-10s / 情绪段 12-15s / 定场段 10-12s；每段 ≤15s（硬约束）。
- **★ Route 必填（2026-09-06 固化，废"默认三镜"）**：每段标 `文戏 / 武戏 / 奇观 / 收束` 四选一，镜数与单镜时长按路由走，禁止无标签均分三镜。

| Route | 镜数 | 单镜时长 | 附加约束 |
|---|---|---|---|
| 文戏 | 2–3 | 3–6s | — |
| 武戏（R2/R3） | 4–6 | 1.5–3s | 镜内无 ≥2s 无攻防空档 |
| 奇观 | 2–3 | 4–7s | — |
| 收束/余韵 | 3–4 | 2–4s | **每 2 秒须有信息或运动变化；单镜 ≥5s 静帧禁止** |

> 历史教训：无路由导致 26/27 段固定三镜——战斗段被压稀疏，收束段切成三张静态明信片。`check-fidelity.py` ②路由 校验本表。

## 二、五层详细分镜（原文 Stage 2 产物，每段一份）

> ★ 五层**逐层必落行**：承接头 / 逐镜拆解 / **戏剧动作（独立一行，不得只融进段标题）** / 退场钩子 / 技术元数据（段号+时长在标题行）——缺任何一层即不完整。

```
## S01 | 10s | <核心动作摘要>

**承接/连续性:** <上段退场状态全文（角色位置/环境/情绪/道具）；开场段写"无(开场)">

**镜号 01 | 0.0s–3.0s | 极近景(ECU) → 中景(MS)**
- 运镜: 固定，焦点从前景物件拉向中景人物
- 画面: 前景=<具体物件细节>；背景=<环境描述>；光线=<光源方向/色温/景深>
- 对白: <如有，角色A：台词>
- 音效: <环境/拟音/配乐提示>

**镜号 02 | 3.0s–6.5s | 近景(CU)**
- 运镜: 固定，低机位，仰拍手部
- 画面: <具体动作/手部细节/皮肤质感/光线>
- 音效: <动作细节音>

**镜号 03 | 6.5s–10.0s | 近景(CU)**
- 运镜: 固定
- 画面: <物件交互特写>
- 音效: <静/风声>

**戏剧动作:** <本段核心视觉事件一句话>

**退场钩子:** <未解决的视觉/情绪元素，喂给 S02 承接头>
```

- 每镜五要素（原文镜头完整性）：景别（必填）、运镜（必填）、具体名词的画面构成（必填）、音效设计（必填）、对白（如有）。
- **★ 运镜行四段式（2026-09-06 固化）**：`景别·视角+角度·运镜·跟随目标`，例 `MS·30°斜角·低机位侧跟·跟随角色A马匹前冲`。只写"WS 固定"不合规（`check-fidelity.py` ⑧镜头规格 校验）。跟随类运镜必须写清跟谁、跟哪个部位。
- 转场逻辑（原文 Stage 2）：match-on-action / 视线匹配 / 180° 轴线规则。

## 三、视频提示词（原文 Stage 4 · 保真铁律）

```
video_prompt = 引用行 + [STYLE] + storyboard_segment.raw_text（逐字，禁止改写/压缩/总结）
             + [执行约束]          # ★ 2026-09-06：仅战斗段与收束段，追加在全文「之后」
```

- 视频提示词 = 该段分镜全文**逐字拷贝**（全部镜头、全部描述、全部技术注记）；`[执行约束]` 为**追加区**，不改写全文，故 `full_text ⊆ video_prompt` 依然成立，保真校验零影响。
- **绝不总结、压缩、改写**；分镜文本已为模型解读优化，任何压缩都会丢失关键视觉细节。
- **★ 引用行按段裁剪（2026-09-06）**：引用行 = 本段画面中**实际出现**的角色 + 本段场景 + 本段出现的道具 + 该场拓扑图。本段任一镜画面中未出现的角色**不得引用**（垫图会诱发模型自行加人）。`check-fidelity.py` ③引用行 校验。
- **★ 高危词转译在分镜阶段完成（2026-09-06）**：写分镜文本时即按 `references/shared-compliance-lexicon.md` 把结果级血腥词转为过程级物理描写；投喂层的扫描只做**验证**，命中即**回改分镜源重跑**，禁止直接手改 `video_prompt`（保真铁律）。`check-fidelity.py` ⑪合规 校验。
- **★ `[执行约束]` 内容（文戏收束段必带；战斗段不走本模板——整段外协，见 `../../references/shared-fight-dispatch.md`）**：机位重申（每镜一句，防长镜漂移）/ 位置锁（甲始终画面左、乙始终画面右）/ 接触锚定（引 visual 中的接触句）/ 本段负面 3 条（按 `shared-quality-gate.md` 附录 B 通用类选取）。缺"位置锁"或"机位" → ⑨执行块 报错。
- 抽样审计：任一不匹配 → 标记全部视频节点废弃 → 重读分镜主文件 → 按逐字规则分批重生成（原文再生成协议）。
- ★ **引用行顺序铁律（★ 2026-09-01 用户定稿；★ 2026-09-04 拓扑图位升级）**：首行引用行顺序固定 = **角色资产 → 场景资产 → 道具资产 → 空间拓扑图（最后一位）**，用实际资产名，图号连续；垫图顺序与引用行一一对应。拓扑图位引用**该段所属场**的拓扑图资产名（带场标识，如 `空间拓扑图·场1=图M`）；同场多段引用同一张，跨场换图，段内图号仍连续。
- ★ **空间拓扑图数量规则（★ 每场一张，2026-09-04 用户拍板，替代旧"每集一张分区制"）**：一张拓扑图只画一场戏（同一连续空间；场景切分口径 = 摄影机是否需要搬运，需要就拆图）；**禁止多场挤一张图**（轴线互相打架）。每场独立产出四件套（空间坐标描述/站位表/机位部署表/轴线与越轴预案表）+ 一条黑白简笔生图提示词（仅黑白灰+一处红色轴线+仅 CAM 编号可作文字+blueprint sketch style），按场写入 `space_maps` 集合（禁复用其他场/其他集）。执行规范单源 = `../../../references/shared-spatial-blocking.md`。
- ★ **风格段/负面词若项目启用（可选扩展）：必须内联完整文本**——禁止「见文首固定段」式占位引用（多条节点逐条手拼必漏）；每条视频提示词都应是**独立完整、可直接复制投喂**的文本。风格段/负面词的文本源 = 风格确认模块的确认风格（动态读取，禁止硬编码，见 SKILL.md §1.6）。

## 五、景别/运镜标准术语（原文标准）

- 景别：ECU 极近 / CU 近 / MCU 中近 / MS 中 / WS 全 / ELS 大远（禁"很近/中近/远景"模糊词）
- 运镜：**本地词表已退役（★ 2026-09-08 运镜词单源化）**——英文拼法统一读中立层 `../../../references/shared-camera-movement.md §八`「听风」列；选型/三轴辨误/易混/环绕代价/战斗段让位 R31 见其 §一~§五。听风侧仍禁"镜头慢慢移动"等模糊词（此约束属听风私有，非公共词表）。
- 机位注明：低机位/高机位/平视；景深注明：前景清晰、背景虚化

## 七、★ tingfeng.json 落盘字段契约（2026-09-06 固化）

> 历史教训：模板只规定 md 文本格式，**未规定落盘 JSON 的字段契约**，导致每次生成时被临时设计、字段遭削减（`camera` 退化成"景别+镜头名"，角度与运镜无处安放，实测 80 镜中 74 镜如此）。字段一定，削减就从"看不见"变成"可捕获的错误"。

```jsonc
{
  "ep": "ep001",
  "battle_segments": ["S03", "S07", "S08"],   // ★ D1 战斗段清单，必填；与 combat_design 同源同步
  "route": "武戏",                              // ★ D7 段级路由（文戏/武戏/奇观/收束）
  "segments": [{
    "id": "S16", "duration": 15, "route": "收束",
    "shots": [{
      "n": 1,
      "ts": "0.0s–2.5s",
      "frame": "WS",                                     // 景别：ECU/CU/MCU/MS/WS/ELS
      "camera": "WS·30°斜角·低机位侧跟·跟随角色A马匹前冲",   // ★ D3 四段式，必填
      "visual": "…主体+动作轨迹+接触部位+受力位移+环境反馈…",  // ★ D5 命中母题时须含其「进词片段」
      "dialogue": "", "sound": "…"
    }]
  }]
}
```

- `camera` 校验正则：`^(ECU|CU|MCU|MS|WS|ELS)·[^·]{2,}·[^·]{2,}·跟随[^·]{2,}$`
- 集级母题条目须含 **`进词片段`**（≤12 字的规格关键串），供 `check-fidelity.py` ⑩母题 机械校验是否进词。
- 校验入口：`python scripts/check-fidelity.py <项目根> --ep N`（退出码非 0 = 该集交付未完成）。
