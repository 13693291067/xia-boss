### 0.1 分解框架（要点索引）

- **分段三维度**：①场景连续性——每段=一个完整戏剧节拍，有明确进/退场状态 ②时长约束——每段 ≤15s（视频模型硬约束）③叙事钩子——以视觉/情绪动势收尾桥接下一段。
- **段解剖（五层结构）**：①承接头 Continuity Header（继承上段退场状态）②镜头拆解 Shot Breakdown（每段 2-4 镜：镜号+时间戳/景别 ECU·CU·MCU·MS·WS·ELS/运镜/画面构成/对白/音效设计）③戏剧动作 ④退场钩子 Exit Hook ⑤技术元数据（时长/节点标识）。

### 0.2 五阶段流程（要点索引）

| 阶段 | 要点 | 副本锚点 |
|---|---|---|
| Stage 1 剧本分析与分段 | 按时间顺序通读；识别节拍（铺垫→冲突→高潮→收束）；标记自然停顿点；段数=总时长/12s；产出段表 `ID\|Duration\|Script Range\|Core Action\|Exit Hook` | 「识别戏剧节拍」 |
| Stage 2 详细分镜 | 逐段：连续性检查（回看上段末帧）→镜头设计（定场/动作/特写/插入）→转场逻辑（match-on-action/视线匹配/180°轴线）→提示词构建（现在时/主动语态/具体名词）；**单帧画面成立性（★ 2026-09-08）按 `../../references/shared-frame-image-grammar.md` 执行：目击位置/环境证据/光源地图按其 §二§三§四，无因不造+删词检验按其 §七** | 「180° rule」 |
| Stage 3 节点创建 | 每段一个文本节点（标题 `S{段号}\|{时长}s\|{摘要}`，内容=**分镜全文**）；每批 5 段 | 节点创建代码（原文逐字） |
| Stage 4 视频生成 | **保真铁律：绝不总结或改写**——提示词=分镜全文逐字；每批 5 个并行；metadata 链接文本节点 | Stage 4 原样 |
| Stage 5 质量保证 | 三重审计（完整性/连续性/保真=抽样逐字比对）；任一不匹配→全部视频节点重生成 | 「三重审计」 |

### 0.3 不可变规则与标准（要点索引）

- **不可变规则**：①段时长 ≤15s ②提示词与分镜文本逐字一致 ③语言一致（产出与输入剧本同语言）④顺序依赖（S{N} 定稿前不得设计 S{N+1}）。
- **连续性标准**：视觉（位置/服装/道具/光线显式传承）、时间（上段"手伸向火"→下段"手悬在火上"）、情绪（段尾表情=下段开头状态）。
- **分镜质量**：每镜五要素齐全（景别/运镜/画面构成/音效设计/对白如有）；描述具体（BAD"角色难过"→GOOD 具体名词神态动作）；标准电影术语+机位+景深。
- **再生成协议**（保真失败，原文）：标记废弃→重读分镜主文件全文→按明确规则分批重生成（`video_prompt = raw_text`，无处理无总结）→更新节点 ID。

### 0.4 其他机制（要点索引）

- 动态段时长：动作段 8-10s / 情绪段 12-15s / 定场段 10-12s，段边界对齐戏剧峰值（横切量化规则见 `../../references/shared-tone-absorption.md`）；
- 跨段母题追踪：母题注册表（出现段登记/描述语言标准化/跨段规格一致）——落点为 §1.5 表 4；
- 并行生成（20+ 段大项目）：Tier1 全部文本节点 → Tier2 视频三批波次 → Tier3 每波后连续性 QA；
- 完整示例（S01 分镜文本与视频提示词逐字对照、节点创建代码、连续性继承示例）→ 见副本对应节。

### 1.3 输出内容格式

- **STYLE/负面词内联**（★ 2026-09-01）：若项目启用风格/负面词扩展（§1.4），每条视频提示词必须**内联完整文本**——禁止「见文首固定段」式占位引用（多条逐条手拼必漏）；未启用扩展时 vp=分镜全文，天然完整。
- **引用行完整性 + 顺序铁律**（★ 2026-09-01，顺序 2026-09-01 用户定稿）：每段视频是**独立投喂任务**，单条提示词必须自包含——首行引用行顺序固定为：**角色资产 → 场景资产 → 道具资产 → 空间拓扑图（最后）**，用实际资产名，图号连续。连续同场景段也必须每段带场景图（不得依赖"上一段带了"）；缺场景 = 模型失去场景锚。机械校验：scene-consistency 的 check-scenes.py 在 shots 带 video_prompt 时自动执行 D 类引用行检查（含顺序校验：拓扑图必须在最后）。
- **故事板拼板规则**（★ 2026-09-01）：格 = **分镜头**（一格一定格瞬间，全部镜头进故事板）；切板点只落在段边界——**一段的所有镜头必须同板，禁止把一段拆到两块板**（贪心按镜头累积段，加段超容则封板；末板不足留白）；板右侧视频位 = **段级**，与本段生视频提示词一一对应。
- **独立交付**（双形态之一）：`outputs/tingfeng-standalone/{epNNN}/`
  - `{epNNN}.md`：分段表 + 逐段五层分镜 + 视频提示词（每段一条，逐字=分镜全文）+ 连续性审计；★ 2026-09-02 起**每段双块**：Seedance 全文块 + H3 六段式块（同步双产，见 §1.9）。
  - `{epNNN}.html`：可复制页面（每段卡片 + 📋 复制视频提示词 + 搜索 + 复制全部）；★ 双产时每段卡片**双复制按钮**（📋 Seedance / 📋 H3）。
- **项目台接入**（★ **必做，2026-09-02 用户拍板：听风分镜产出必须同步接入项目台听风电影工作台，禁止只出独立文件不进工作台**）：`outputs/<工作台模块名>/{epNNN}/<模块名>.json`（本项目实例：听风电影工作台），字段契约 `segments[{id,duration,script_range,core_action,continuity_header,exit_hook,shots[{n,ts,frame,camera,visual,dialogue,sound}],video_prompt,full_text}]`——字段命名属输出格式适配，**内容仍按原文生成**；★ **2026-09-02 H3 双产扩展**：每段增 `video_prompts:{seedance,h3}` 双字段（seedance=video_prompt 同值，h3=按 quality-spec 同步产出的六段式，见 §1.9），工作台直接采用；★ **2026-09-03 P0-1 保真契约扩展**：每段增 **`full_text` = 该段分镜全文（逐字，与 standalone md 中该段正文一致）**——原文 Stage 3 `full_storyboard_text` 的落盘形态，是 check-fidelity.py 机械校验保真的比对源；build-data-js.py 对 segments 字段透传，无需改构建脚本；★ **2026-09-04 拓扑图按场集合扩展**：ep 级字段由单数 `space_map_prompt/space_map_image` 升级为集合 `space_maps:[{name,prompt,image,ready}]`（每场一项，name=场标识如"空间拓扑图·场1"；段级 `segment.space_map` 存所属场拓扑图的 name 供垫图对应）——旧单数字段保留读取兼容（旧项目数据视为单项集合）；空间字段 merge 见 build-data-js.py；★ **2026-09-06b 双语扩展**：`space_maps[]` 每项增 `prompt_cn`（中文理解稿，与 `prompt` 英文执行版同轮结构化对译——规范见 `../../references/shared-spatial-blocking.md` §十双语条款），缺失由 check-fidelity ⑫ 报缺；旧项目单字段数据兼容读取。
- **交付纪律（★ 2026-09-02；★ 2026-09-03 增保真硬门禁；★ 2026-09-04 增投喂前序列）**：每集完成时**双形态必须同时产出**（standalone md/html 供审阅转发 + tingfeng.json→build-data-js.py 同步 SQLite 供工作台查看/生图/拼故事板），**且必须跑 `scripts/check-fidelity.py <项目根> --ep N` 通过（退出码 0）**——保真包含/段规则/引用行/H3 契约任一不清零 = 该集交付未完成；缺任一形态或校验未过 = 该集交付未完成；**实际投喂生成前**再按 `../../references/shared-feeding-checklist.md` 六步指针序列过检（Step 5 战斗段：外协提示词按 `../../references/shared-fight-dispatch.md` 回流契约校验[负面四禁+诱因词] / 高危词→`../../references/shared-compliance-lexicon.md` 转译），漏过任一步该条投喂作废；分级口径以 `../../references/shared-quality-gate.md` 为准。
- 生成脚本模板：`build_standalone.py`（数据驱动，换集改数据即可）。

### 1.5 Stage 1 五表强制产出（★ 执行纪律，2026-09-01 实战教训固化）

> **★ 分段颗粒度贯通挂接（★ 2026-09-05，横切单源）**：Stage 1 分段规则升级——**上游有秒段级剧本时**（经 §0.6 剧本写作流程产出的分集剧本，自带 90s 循环与颗粒度段），分段**沿剧本颗粒度段边界 1:1 切组**（剧本一段 = 一个听风 segment，10~15s 弹性、上限 15s）；上游只有小说/无剧本时，按 `../../references/shared-script-writing.md` 的颗粒度逻辑自切（先按 90s 循环框事件，再按档位切组）。每个 segment 的提示词按该组**节拍功能**展开，段头标注功能名（如"本组节拍：压迫升级"）——剧本层、分镜层、提示词层三层同构。生成段 10~15s 弹性与聚合规则见 duration-control §二。

> **Stage 2 衔接与台词挂接（★ 2026-09-04 二次采纳，横切单源）**：①**镜头衔接**按 `../../references/shared-transitions.md` 执行——原文转场逻辑的 match-on-action/视线匹配分别归入**一式·动作连续切/四式·视线引导切**（对齐表见其 §四），180° 轴线仍由空间拓扑规范约束，两者并行；分镜转场处与视频提示词的衔接描述按"式别名+动机一句话"书写（如"五式·遮挡过渡：角色A躯干掠镜，切院内"），禁止无动机硬切；视听省略（省冗余过程/环境代击打）用于过场镜与蓄力释放。②**台词字段**生成时逐句过 `../../references/shared-dialogue-doctor.md` 七维快速复核（重点：辨识度/类型语感/节奏音乐性），节奏维度直接落语速卡；金句台词必配气口（时长控制）与反应镜（跨段反应·三手法）。

> **Stage 2 时长控制挂接（★ 2026-09-04 新增，横切单源）**：Stage 2 逐段排镜强制按 `../../references/shared-duration-control.md` 执行——①**段落路由**（文戏/武戏 R1R2R3/奇观）决定估时公式，段头标注路由与档位；②每段组内**时码账本**从 00:00 起排、首尾相接零缝隙；③台词先过**语速公式**（三档语速，判定区间 [字数÷5, 字数÷3.5]），金句后强制 0.3~0.8s 气口显式写进时间轴，单句 >18~24 字强制拆 2~3 镜（每镜 ≤18 字）；④**节奏铁律**（同运镜≤2s / 同景别≤3s / 情绪拐点落 8~12s / 开局 0~1.5s 见肉 / 无静止段——蓄力皆在运动中）；⑤溢出**三板斧**（拆/并/砍），都动完还超回第 1 层加组，禁止压语速硬塞；⑥交付物含**语速自检卡**（每台词一行）+ **两道账**（Σ镜=段时长、Σ段=总预算，写入自检表）。方法论原文"每段 ≤15s、2-4 镜"不变——本挂接解决"15s 之内怎么解"，原文与本规范冲突时按 shared-duration-control §〇 裁决序取更严者。

### 1.6 风格源规则（★ 全项目单一风格源，2026-09-01 实战确立）

> **反面教材**：生视频提示词的英文风格段/负面词**硬编码**在生成函数里，内容是早期项目的过时风格——与本项目确认风格、资产图实际风格全部冲突。

- **唯一风格源 = 风格确认模块的确认结果**（确认风格里的通用风格段 `style_instructions` + 负面词 `avoid_instructions`）。
- **生视频提示词**：STYLE 段与负面词**动态读取确认风格**，禁止硬编码字符串；生成函数封装为统一读取函数（确认风格缺失时才回退默认值）。
- **生图提示词**：确认时把风格段**作为前缀固化**进每条资产 prompt（确认一次、前缀跟随每条 prompt）。
- 机制结论：换风格只需在风格确认模块重新确认一次，资产与生视频提示词全部跟随。
- 本条为项目工程机制（适配层）；方法论原文不含风格源概念。

2. **用户确认调度单** → Read `../seedance-combat-prompt/SKILL.md`，把调度单八字段作为其「收集信息」输入，按其工作流（完播率公式/32 条执行规则 R1–R32/兵器专项资料库按其触发条件加载）生成 15s 提示词；
3. **用户确认产出** → 回流：`full_text` = `video_prompt` = `video_prompts.seedance` = 提示词全文（自足，无 [引用行]/[STYLE]/[执行约束] 文戏外壳）；`video_prompts.h3` 留空；`shots` 空数组；
4. **负面四禁并入**：`武器形态漂移/动作接触失真/力量反馈缺失/慢动作滥用` 四条必须出现在该段负面提示词行内（与 seedance 标准负面词合并不替换）——check-fidelity ⑦ 机械校验；
5. **合规转译**：按 `../../references/shared-compliance-lexicon.md` 扫正文高危词并物理转译（此步在 xia-boss 侧做）。
