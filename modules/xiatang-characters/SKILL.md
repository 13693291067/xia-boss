# 虾塘（角色/场景/道具/声线资产库）功能 100% 还原

## 0. 还原目标（一句话）

**虾塘把虾料摄入后的抽象角色/场景/道具，变成带定妆图（肖像）、身份图、声线的"可用资产"，并为后续虾镜（剧集）的每个镜头提供身份一致的视觉锚点。**

100% 还原 = 行为等价，验收标准：

```
同样的项目数据 → 同样的角色/场景/道具列表响应结构
同样的生成请求 → 同样的任务入队（task_type/scope/payload）与计费元数据
同样的资产操作 → 同样的文件落盘（assets/ 目录结构）与历史回滚
同样的边界输入 → 同样的错误响应（already exists / novel_import_required 等）
同样的下游 → 身份图/声线能被虾镜 pipeline 正确消费（identity_plan/identity_images）
```

## 2. 还原工作流

### 2.1 开工前：选择还原模式

- **源码克隆模式**（原项目在本机，如 `C:/Users/123/Desktop/AI学习资料/dramaclaw`）：
  1. 读 `references/code-map.md` 拿到文件级代码地图
  2. 按地图逐个文件搬运/适配（保留所有端点路径、payload 结构、错误文案、文件落盘规则）
  3. 用 §3 验收清单逐条核对
- **从零重写模式**（无原项目）：
  1. 按 code-map.md 中的功能规格逐域实现（角色→肖像→身份→声线→场景→道具）
  2. 用 §3 验收清单逐条核对

### 2.2 执行纪律（强制）

1. **逐域还原**：严格按 角色→肖像→身份→声线→场景→道具 顺序，每域完成即自测。
2. **契约不漂移**：所有端点路径/请求体/响应结构/错误文案必须与 code-map.md 完全一致。
3. **行为等价优先**：允许技术栈不同，但 API 语义、文件落盘规则、状态流转必须等价。
4. **主角唯一性**：is_main 只能一个；新设主角须 unset 其他主角；启动时修复重复主角。
5. **资产可回滚**：每次肖像/身份图变更前备份，历史可 restore。
6. **还原后再交付**：完整实现 + 自测通过后，输出验收清单核对结果，再向用户汇报。
7. **人与物分离判定（道具方法论·小墨版）**：判断"物品进角色资产还是独立道具"的标准 = **是否需要道具师单独建模**——武器/防具/功能性容器/信物/场景道具 → 独立道具资产；饰品/穿戴/身体标记（纹身/伤疤/胎记）→ 并入角色描述/定妆。同一道具被多角色使用 → 只建一个道具条目，所有角色【关联道具索引】指向同一编号（防一把剑被设计成两个样子）。
8. **设定提取六要素（角色方法论·小墨版）**：产出定妆提示词之前，先为每个角色产出**六要素设定段**（一整段文字：年龄/性别/肤色/发型发色/五官特征/服装），遵循"原文优先 → 合理推导（标注推导）→ 设计建议（标注建议）"三级来源，禁止凭空捏造与原文矛盾的特征；六要素段作为定妆提示词的设定依据，抓辨识度最高 1-3 个五官特征即可，不过度展开。**与虾料人物小传对齐（★ 2026-09-03）**：docs/03-characters 的人物小传（虾料生产事实⑤）已登记的年龄/族裔地域/生活痕迹/声音气质条目视为"剧本事实级"输入，六要素不得与小传冲突；冲突时回查原文，原文赢。
9. **提示词英文纯净范式（跨模块强制，2026-08-19 用户确认，与虾镜纪律 17 同步）**：所有**资产类生图提示词（角色定妆/身份图/场景/道具）必须用英文纯净描述**——只写镜头拍得到的画面内容（人物/服装/五官/动作姿态/场景/光线/道具细节）+ 质感/氛围段；**禁止把台词、人物性格说明、剧情叙事、音效词写进提示词**（如"正在喊杀"“正在说话”这类行为叙事 → 改为可拍画面"举剑冲锋姿势"）。中文只允许出现在资产名称/标签/元数据字段，不进提示词正文。风格与质感段（style_instructions/avoid_instructions）按虾格三要素规范。
9a. **提示词双语双产（★ 2026-09-06b 用户拍板，与纪律 9 配套）**：所有资产类生图提示词（定妆/身份图/四视图卡/场景/道具/拓扑图）**同轮双产**：先写**中文定稿**（`prompt_cn`，用户理解审稿用——身份/服装/道具/光影/构图/负面逐段可读），再**结构化对译**成英文（`prompt`，生图执行版）。对译纪律：逐段一一对应（渲染介质句/视觉参考/主体/服装/道具/光影/构图/负面禁令），禁增删要素；专有名词英文用「拼音+括号特征注」；纪律 9 的英文纯净约束只作用于 `prompt` 正文，`prompt_cn` 是元数据理解层（与资产名/标签同级），不进生图链、不受"英文纯净"豁免冲突。双字段：`prompt`=EN 主字段（生图链路与 check-assets 指纹零改动），`prompt_cn`=CN 理解层；中文稿只读（弹窗手改英文不回写中文，卡上标注手改状态）。
10. **资产命名规范（★ 2026-08-28 事故固化，强制）**：资产名（角色/场景/道具/key-scenes）**禁止包含特殊字符**——`+`、`【】`、`·`、`/`、`\`、空格、引号等一律禁用（生图文件名与 API 请求会因特殊字符失败/转义错乱；教训：三个带特殊字符的资产名（如"XX+XX"、"【书名】角色"、'XX+XX'）生图失败）。只允许中文/英文/数字组合。改名纪律：必须**全链路同步**（assets-registry.json + asset-prompts.md + world.json/ingest label + handoff + 已产出分镜引用 + rebuild 项目台），并跑残留 grep 验收（`grep -rn "旧名" outputs/` 应为空）；角色可配 aliases（如某系统类角色全名过长 → aliases 配简称，保证分镜简称可匹配）保证分镜简称可匹配。

11. **角色资产原文锚定（★ 2026-09-01 事故固化，强制）**：

    > **反面教材**：角色形象按人物表标签臆造（功能标签 → 臆造出年龄/体型完全不符的形象，如按"算账"职能标签臆造出幼态体型，而出场章节原文明写成年壮硕），与出场章节原文全面冲突——分镜严格贴章节原文拍摄时冲突爆发，资产返工。**根因：人物表规划 ≠ 正文实际写作（网文创作常态），且登记后无人与原文对账。**

    - **闸门 1（创建时·全书扫描先行）**：新角色建资产前，**全书检索该角色全部出场**，产出「原文证据表」（章节 × 出现次数 × 关键描写原句，覆盖外貌/年龄/体型/服装/能力/性格六维）；从证据表划分**身份阶段**（成长弧：章节区间→身份名），不从标签直接定形象；人物表标签与原文冲突 → **原文赢**，标签只留"角色定位"字段。判定标准：建身份前能回答"这个形象的每一条特征出自哪一章哪一句"。
    - **闸门 2（登记时·身份=章节区间+依据行）**：每个身份绑定章节区间字段 `chapter_range`（如 `chNNN-chNNN`）并带 `evidence` 原文依据行（章节+原句摘录；推断项标注"推断"+理由）；prompt 每条外貌特征可追溯；角色出现新阶段 → **加新身份不改旧身份**（旧章节的戏还要用旧形象），旧身份仅在正文明确改写时修正。
    - **闸门 4（数据源·库唯一权威）**：资产状态（图存在性/身份结构）一律查数据库快照，**不查导出文件**——registry 等导出物带 `exported_at` 标识、仅作离线参考，且导出必须适配下游消费方契约（字段名/文件查找规则），导出后跑一次下游流程验证。
    - 闸门 3（使用时·分镜引用前形象匹配）由分镜模块的 Stage 0 执行，见 storyboard-cinematic §1.7。

12. **角色状态依赖门禁（★ 2026-09-03 集成）**：血缘亲属、同一人的换装/受伤/年龄/变异、双胞胎克隆、宿主与变身、连续破损，一律按**有向依赖**管理——建角色清单时在 assets-registry 登记每条 `dependencies`（type/upstream/relation，见 `references/character-dependency.md`）；**有上游依赖者只输出等待卡，上游主图 image_ready 且通过回传验证闸门前不得写完整下游提示词**；血缘只继承 2-4 项家族特征（像血亲但不是同一张脸），状态图保持原脸身高骨架只改剧情明确部分；变异程度剧本未明确时只问 1 次（H1 人类主导 / H2 均衡 / H3 野兽主导）；变异多阶段逐阶段登记，不得用最终形态污染早期形态。同层无依赖角色同批出词、整批确认后解锁下一层。check-assets 第 ⑧ 项校验依赖完整性。

> **提示词合规 ≠ 出图合格**——生图模型对风格词的响应能力不确定，必须由本闸门兜底，禁止沉默通过。

### 资产提示词注入模式（★ 强制，2026-09-02 方案 D：弱风格词事故固化）

## 角色资产图规范（★ 独立文件调度，2026-08-21 收敛）

角色资产图 = **主图（证件照式定妆照） + 身份图两图制（① 定妆照 + ② 四视图角色卡）**。完整规范在独立文件，**产出对应提示词时加载**：

- `references/character-assets.md` —— 人物资产图规范全集（主图证件照式 / 身份图两图制 / 人物纯背景资产图通用要求 / 妆造设计 / 真实感 / 锁脸铁律 / 英文纯净+自动校验）。**产出角色资产图提示词时加载。**
- `references/character-sheet-4view.md` —— 四视图角色卡模板（**上下两段式·用户钦定固定模板**）。**做身份图第二图（四视图角色卡）提示词时加载（提示词固定，逐字复制）。**

**核心铁律摘要（详细规范见 character-assets.md）**：

1. **主图 = 证件照式标准像**：3:4 竖版，85mm f/1.8，正面肩以上头像构图、画面只到肩膀上沿，纯色背景、均匀棚拍光、无姿态动作；禁写腰以下细节；负面词必含露肩/锁骨/短袖/半身构图等。
2. **身份图两图制**：① 定妆照（该身份造型正面基准图）＋ ② 四视图角色卡（**上下两段式定妆参考板，提示词固定为用户钦定中文模板**，见 character-sheet-4view.md §A）；两图同面容同服装，背景纯色（禁止场景/环境元素）。
3. **人物纯背景资产图通用要求（★ 角色资产图必须符合）**：纯中性背景；无场景、无其他人物、无文字、无尺寸标注、无说明标签、无水印；身体比例统一，年龄/发型/面部/服装/鞋履/道具统一；正侧背视图结构一致；禁服装漂移、左右道具错位、多余手指、肢体畸形；人物自然中性站姿。
4. **定妆照须符合妆造设计**（剧本转分镜人物妆造 §11.2）：保持角色面部结构不变，只做妆面/发型/服装/配饰/色彩基调变化，避开网红脸与影楼照既视感。

## 无人物场景资产图规范（★ 独立文件调度，2026-08-21 收敛）

**三类概述（详细规范见 scene-assets.md）**：

1. **A 全景鸟瞰图（空间基准图）**：每场景一张高机位鸟瞰图（2.39:1），完整展示空间结构/出入口/人物路线/光源位置/高低差；地理结构符合剧情行动逻辑；**后续所有镜头以该图作为空间连续性依据**；空镜约束；与上帝视角（90° 正俯平面布局）并存不冲突。
2. **B 场景多机位九宫格图**：每场景一张 3×3 连续排版图，九个机位（正面全景/反向全景/左侧/右侧/高机位俯拍/低机位仰拍/主要入口视角/核心区域中景/关键材质或道具特写）；**九个画面属同一空间**（结构/门窗/道路/道具/光源/时间天气一致，无空间跳变）；无人物无生物无文字无水印；与「场景切换视角（7 视角）」**并存不替代**（视角图=单视角参考垫图，九宫格=一张图 9 格空间一致性总览）。
3. **C 大场景总览鸟瞰图**：一张图展示多个关键场景之间的整体地理关系（距离方向/人物行动路线/河流道路建筑群山体桥梁广场树林）；标志性建筑位置明确；各场景必须能通过合理路线到达；画面内不得出现文字/箭头/图标/路线标注（靠道路地貌建筑自然呈现）；无人物无生物。
