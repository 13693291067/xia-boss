# shared-fight-dispatch · 战斗段外协调度协议（横切单源，★ 2026-09-07 v3 新增）

> **适用**：听风线 / 虾镜线全部分镜流程——凡剧本/分段中出现打斗/对决/追杀/突围/守护/群战段落时强制遵守。
> **变更背景（★ 2026-09-07 用户拍板）**：打斗戏设计方法论（原 fight-scene-director 模块）已整体移出 xia-boss 并归档；打戏提示词改由内置模块 **`modules/seedance-combat-prompt/`**（Seedance 2.0 打戏提示词生成器，原封不动挂载）统一生成。xia-boss 本体**只判断、不设计**：判定战斗段、抽段、组装调度单、回流提示词。
> **分工铁律**：打戏内容的判断（是不是打戏/边界在哪/结局如何）归本协议与分镜线；打戏内容的**设计**（招式编排/运镜/特效/节奏）全部外协给 seedance-combat-prompt——**禁止在 xia-boss 内自行编排招式链或改写外协产出的动作设计**。

---

## 一、战斗段判定与登记（保留原纪律，判定权不下放）

1. **触发判定**（Stage 1 产出后）：分段表/节拍表中某段 Core Action 含打斗/对决/追杀/突围/守护/群战类内容；或用户点名；或 QA 发现状态断裂。判定依据沿用 `shared-duration-control.md` 段落路由（文戏/武戏 R1R2R3/奇观）。
2. **登记落盘**：战斗段清单必须写入集数据 **`ep.battle_segments`**（段号字符串数组，如 `["S03","S07"]`）；区间写法（`S07-S08`）落盘时展开为连续段号。`check-fidelity.py` ⑦ 缺登记即报错，禁止静默跳过。
3. **★ 战斗段独立分镜（v3 核心纪律）**：战斗段**整段抽出，禁止与文戏混段分镜**——
   - 战斗段不做听风五层拆镜、不进 Stage 2 逐镜设计（`shots` 留空）；
   - 相邻文戏段/收束段不得夹带打斗动作描述；战斗段的直接后继段（余韵/收束）仍按收束段简化门禁走文戏流程；
   - 战斗段的视频提示词 = 调度单外协 seedance-combat-prompt 的产出**整段回流**（见 §四），两者不许手工混写。

## 二、调度单固定格式（v3 契约，八字段，顺序固定）

每张调度单对应**一个 ≤15s 的战斗子段**。格式如下（`{}` 为从项目资产取值的槽位）：

```
【打戏调度单 #NNN】
segment_id：{段号 + 集数 + 起止时码}（>15s 的战斗段拆多张单：#NNN-1/#NNN-2/…，每张 ≤15s）
群战人数结构：一对一 | 一对多（A方1人 vs B方N人，列参战者名单）| 团队 NvM | Boss 战
              {多人时写明焦点规则：镜头焦点锁定哪 1–2 人，其余参战者的攻防如何轮换入画}
角色A：{名 + 拳法/兵器绑定 + 劲气色/主色}          ← 从虾塘角色卡「战斗语言」字段取
角色B：{同上；群战时列为 B 方全部参战者并标注焦点 1–2 人}
场景：{风格质感 + 空间地点 + 环境细节，三段式}      ← 从虾塘场景资产取，站位/轴线与所属场拓扑图一致
视觉风格：{虾格 creation-direction.json 风格锁对应字段，原样搬运，禁止改写}
战斗节奏：碾压 | 拉锯 | 逆转（+ 强度档 R1/R2/R3；如有开局冲击/情绪拐点位置的特殊指定一并写入）
结局：{胜负 + 不可改剧情事实，逐条列出（必须出现的救援/受伤/反转/代价），外协产出不得违背}
特殊要求：{走位/画幅/平台 + 段间衔接：本单起始状态 = 上一单末状态（首单 = 承接上段退场钩子，末单 = 交出退场钩子给下段承接头）}
```

**字段来源速查**：角色A/B ← 虾塘 `character-assets`（战斗语言：拳法绑定/劲气色）；场景 ← 虾塘 `scene-assets`；视觉风格 ← 虾格 `creation-direction.json`；节奏档与结局 ← 剧本事实 + `shared-duration-control` 段落路由。缺项（如虾塘未建资产）先补建资产再调度，**禁止向 seedance-combat-prompt 传空槽位让它猜**。

## 三、调度执行方式

1. **Read** `modules/seedance-combat-prompt/SKILL.md`，按其「生成工作流」执行，把**调度单八字段**作为其第 1 步「收集信息」的完整输入（等于其使用模版的角色A/角色B/场景/视觉风格/战斗节奏/结局/特殊要求 + 本协议扩展的 segment_id 与群战人数结构）；
2. 其 references（iron-laws-32 / 兵器专项资料库等）按其内部触发条件正常加载；**群战/一对多时**：人数结构映射为其「对战双方」框架（A方/B方两个阵营），焦点轮换要求写进特殊要求字段，由其按铁律编排；
3. 产出 = 该子段的 **Seedance 15 秒打戏提示词**（含其标准负面提示词行）；
4. 调度过程停下等用户确认的门控不变：调度单先给用户过目确认，再调 seedance 生成；产出提示词回 flows 前再给用户过目。

## 四、回流规则（v3 数据形态）

seedance 产出回流进 tingfeng.json / 分镜数据的战斗段条目：

| 字段 | v3 契约值 |
|---|---|
| `route` | `"武戏"`（已登记 battle_segments） |
| `full_text` | seedance 提示词**全文**（含负面提示词行） |
| `video_prompt` | = `full_text`（自足，无 [引用行]/[STYLE]/[执行约束] 文戏外壳） |
| `video_prompts.seedance` | = `full_text` |
| `video_prompts.h3` | **留空**（战斗段不做 H3 双产，H3 仅供文戏段） |
| `shots` | 空数组 |

1. **负面四禁并入**：`武器形态漂移 / 动作接触失真 / 力量反馈缺失 / 慢动作滥用` 四条战斗关键负面词必须出现在该段负面提示词行内（seedance 标准负面词 ∪ 四禁，合并不替换）——`check-fidelity.py` ⑦ 机械校验；
2. **多单衔接**：>15s 战斗段拆多张调度单时，后一张单的「特殊要求·段间衔接」必须声明前一张单的末状态；回流时各子段按各自 segment 落位，相邻子段的提示词首尾状态由人工/收束段门禁复核；
3. **合规转译**：回流后、投喂生成前，按 `shared-compliance-lexicon.md` 对提示词正文做高危词转译（此步在 xia-boss 侧做，seedance 不负责合规）；
4. **门禁适配**：`check-fidelity.py` 对 battle_segments 登记段走**早退分支**——只查 ①保真（full_text ⊆ video_prompt）+ ⑦诱因词 + ⑦负面四禁，豁免 ②段规则镜数/③引用行/④H3/⑧镜头规格/⑨执行约束（文戏门禁不适用于外协段）；`postprocess_tingfeng.py` 对登记段跳过文戏重建管线（不重建 full_text/不产 H3/不追加执行块）。
