# 无人物场景资产图规范（场景资产图全集 · 独立调度文件）

> 来源：虾塘「场景全景鸟瞰图规范」+ 剧本转分镜无人物场景资产图规范（§13），2026-08-21 提取为独立文件。**产出场景资产图提示词（A 鸟瞰 / B 九宫格 / C 总览）时，加载本文件。**

## 0. 定位

所有关键场景都必须制作**无人物场景资产图**，分三类（A/B/C），全部遵循**场景空镜铁律**（提示词只写环境本身，禁止出现人物、人群、角色动作、人物服饰等描述——见虾塘 SKILL.md「场景提示词铁律」）。

**★ 光源可溯源通用句（★ 2026-09-04 采纳，跨风格适用）**：所有场景提示词的光线描述必须写**明确物理发光源**（日景：窗棂天光/丁达尔斑驳阳光/天空散射；夜景室内：钨丝灯/日光灯管/烛火/霓虹反射），阴影呈青灰/暗棕环境漫反射，禁死黑、禁无来源轮廓光与漂浮发白；写实线完整版见虾格 `p1-cinematic-baseline.md` §6 纪律 4（含日景防冷光转译）。违反 = 质检 P1（`shared-quality-gate.md`）。

**★ 空镜画面语法两条（★ 2026-09-08 采纳，横切单源 `../../../references/shared-frame-image-grammar.md`）**：
1. **环境携带证据**：空镜提示词须能回答"若人物全部消失，这个空间仍能暗示刚才发生了什么"——按该场景的剧情状态与使用痕迹选**少量有因果的细节**（被移位的物件/未完成的动作痕迹/使用磨损），写入画面内容段；禁堆无因果的陈设杂物清单（"漂亮但没故事"的空景不合格）。
2. **光源地图组织光线段**：光线描述按其 §四光源地图五项组织——主光源（来源/方向/软硬/色温倾向）、辅助光源、阴影区、高光面、曝光行为——先画光源图再落词；上文"光源可溯源通用句"是本清单的最低裁量（跨风格强制），本条给完整决策框架。

**★ 数据纪律**：本文件（skill 内）只存规范模板；具体每项目的场景资产图是项目产物（`outputs/` + `assets/scenes/`），禁止写入 skill。

## A. 全景鸟瞰图（空间基准图，★ 已有规范合并）

每个场景额外产出一张**全景鸟瞰图**，作为空间连续性依据——**后续所有镜头以该图作为空间连续性依据**。

- **拍摄**：高机位鸟瞰 / 近垂直俯拍；2.39:1 变形宽银幕，ARRI Alexa 数字电影机质感。
- **空间结构**：完整展示场景空间结构——核心元素位置（如"中央王座居中、两侧柱体对称"）、道路、建筑、房间、门窗、楼梯、桥梁、河道、巷道和主要设施；清晰展示主要入口和出口、人物可能经过的路线、主要光源位置、场景高低差、前后空间的连接关系。
- **地理逻辑**：地理结构必须符合剧情行动逻辑，不得出现互相冲突的通道或建筑结构、不得出现无法解释的封闭死路、不得随机增加建筑。
- **约束**：无人物、无生物、无文字、无水印；材质真实。
- **与上帝视角的关系（并存）**：上帝视角 = 90° 垂直正俯（平面布局+线稿，9:16，供调度图线稿源）；全景鸟瞰图 = 高机位俯拍（2.39:1，场景资产/空间基准）。两者用途不同，并存不冲突。

## B. 场景多机位九宫格图（★ 新增，2026-08-21）

每个关键场景生成一张连续排版的 **3×3 九宫格图**。

**九个机位建议包括**：

1. 场景正面全景
2. 场景反向全景
3. 左侧视角
4. 右侧视角
5. 高机位俯拍
6. 低机位仰拍
7. 主要入口视角
8. 核心区域中景
9. 关键材质或道具特写

**要求**：

- 九个画面属于**同一个空间**：建筑结构、门窗数量、道路方向、道具位置、光源方向、时间天气完全一致。
- **不得出现空间跳变**。
- 无人物、无生物、无文字、无水印。
- 与「场景切换视角（7 视角）」**并存不替代**：7 视角（正面/左侧/右侧/背面/斜侧/俯视/45°俯视全景）用于单视角参考垫图；九宫格用于一张图 9 格的空间一致性总览——用途不同，各自保留。

## C. 大场景总览鸟瞰图（★ 新增，2026-08-21）

用于展示**多个关键场景之间的整体地理关系**。

**要求**：

- 完整展示故事主要发生区域。
- 展示不同场景之间的距离和方向。
- 展示人物可能的行动路线。
- 展示河流、道路、建筑群、山体、桥梁、广场、树林或其他主要地貌。
- 标志性建筑必须位置明确。
- **各场景之间必须能够通过合理路线到达**。
- 画面中不得出现文字、箭头、图标或路线标注——通过道路、河流、地貌和建筑**自然呈现**空间关系。
- 无人物、无生物、无水印。

## D. 场景资产补建判断规则（★ 2026-08-22 用户拍板，防"过渡场景漏建"）

**原则**：拆镜编号表里的**每个 SC 都必须有对应场景资产**（或明确判定省略并登记原因）——"过渡/单镜场景可省"的旧做法导致生图引用缺图、场景一致性靠文字兜底打折（教训：示例剧第 1 章 SC-02 餐厅门口/SC-03 车内/SC-05 病房漏建，结尾视觉锚点戏与回忆戏场景质量受影响）。

### D1. 必须建资产（缺一不可）

1. **主叙事场景**：对话/交锋/反转的主战场（西餐厅、客厅、公司办公区）；
2. **关键戏场景**：爆点/情感点/收网戏所在场景（宴会厅、法院门口、律师办公室剪影）；
3. **视觉锚点场景**：离场/收尾/时间跨度承载（餐厅门口·豪华轿车离场、清晨窗边晨光、电梯楼道）；
4. **情绪承载场景**：回忆/独白/心理戏所在（病房、书房、出租车内、车内）；
5. **场景镜数 ≥2** 的任何 SC。

### D2. 唯一可省略（需登记）

- 镜数 **<2** 且纯过场、无情绪承载、无视觉锚点的空过场——省略也要在 scene_map 登记该 SC 为场景描述文字（保制作页显示可读）。

### D3. 补建流程（五步）

1. 检查点 A 编号表 → 对照 `outputs/xiatang/assets-registry.json` 的 scenes 数组，列出缺失 SC；
2. 补 `assets-registry.json`：`{name, desc, prompt}`（prompt = 英文场景生图提示词，16:9 cinematic，无人物空镜，光线/氛围/空间三要素）；
3. 补 `outputs/xiatang/asset-prompts.md`：`## 场景 {name}` 段 + 代码块（build 从标题匹配 prompt，**registry 的 prompt 字段不生效**，必须写 asset-prompts.md）；
4. 更新该集 `outputs/xiajing/ep{NNN}/shots.json` 顶层 `scene_map`（覆盖**该集全部 SC**）；
5. build → 校验：`scene_name 未映射镜头 = 0`。

### D4. scene_map 契约

- 每集 shots.json 顶层 `scene_map: {SC编号: 场景资产名}`，**必须覆盖该集全部 SC**；
- 制作页显示 `scene_name || scene_map[scene_tag] || scene_tag`；首帧/尾帧生图场景引用取同一链路；
- 无映射 = 制作页显示 SC 编号 + 生图无场景参考图 = **缺项，退回补齐**。

## A2. 空间基准图 layout（★ 2026-09-10 并存新增；§A / §B / §C 与上帝视角一律不动）

> **并存声明**：本节是**新增第四类场景资产**，不替代、不改写 §A 全景鸟瞰图、§B 九宫格、§C 总览鸟瞰、也不改「上帝视角」`plan`/`plan_sketch` 的任何既有行为与出图。既有资产已生成的图全部保留。
> **职责**：同时锁「布局＋外观」，是**场景一致性（跨集、跨机位）的唯一图级载体**。

### A2·1 为什么需要它（一句话因果）

单角度的场景图保不住一致性，因为**漂移恰好发生在它没画到的那一面**：一张"从院门往里看"的图把南面画清楚了，换到灶前特写或从屋门口朝外拍时，模型手里没有那一面的依据，只能脑补，于是灶跑到西边。顶视把四面边界、四角、院心、门外一次全画到，**它没有"没画到的一面"**。

### A2·2 与 §A 的差别（别混用）

| | §A 全景鸟瞰图 | A2 空间基准图 layout |
|---|---|---|
| 画幅 | 2.39:1 固定 | **16:9 固定**，与成片画幅解耦 |
| 视角 | 高机位／近垂直俯拍，未钉机位侧 | **3/4 斜俯视轴测 55°，机位钉在南侧上空朝北看** |
| 锚点 | 自由描述（"中央王座居中"） | **逐字派生自 `space-truth.json`，禁止增删** |
| 围合 | 未要求 | **四面必填**（见 A2·3） |
| 光 | 未约束时段 | **中性基准光，不携带时段特征** |
| 用途 | 场景氛围／空间参考 | **布局＋外观权威；垫图 `role=layout`** |

### A2·2·补 承载字段（★ 2026-09-10 3.5.12 补，此前 A2 无落库位）

> 实测缺口：A2 定为"第四类场景资产"，但 `assets-registry.json` 的 `scenes[]` 里**没有任何承载字段**——layout 的图与就绪状态无处登记，于是"layout 是否存在"根本查不出来，只能靠人记。**没有落库位的资产类型等于不存在。**

- `scenes[].layout_image`（可选）：A2 基准图路径，如 `assets/scenes/<场景名>-layout.png`。
- `scenes[].layout_ready`（bool）：A2 出图并通过纪律 18 回传验证后置 `true`；**缺省视为 false**。
- 由 `gen-layout-prompt.py` 派生提示词、用户出图后回传，虾塘负责置位并同步项目台。

### A2·5 缺位兜底：layout 未 ready 时，被垫图的场景空镜必须自带门通向声明（★ 2026-09-10 3.5.12）

> **一句话因果**：A2 是布局权威，但它没出图时，实际垫图会**静默降级**到不要求管布局的场景空镜图，模型便自行补全空间关系——实测把堂屋门画成"开门见海"、把门槛挂到院门上。**缺失本身不可怕，可怕的是缺失被静默兜底**（与 `check-scenes` D2 同源逻辑：引用了没生成的图必须报警）。

- **触发条件**：该场景 `image` 文件**真实存在于盘上**（即会被垫图）**且** `layout_ready != true`。
- **要求**：正向段必须含一行机读标记 `Doorway relation:`，写清三件事——门开向哪儿、门外可见什么、明令不可见什么。零散的自然语言描述不算（门禁检不出，等于没写）。
- **自动解除（★ 3.5.13 改用盘上事实）**：显式 `layout_ready = true`，**或**约定路径`assets/scenes/<场景名>-layout.png` 真实存在——满足其一即解除，分工回到"A2 管布局、空镜管氛围"。不依赖"有人去把布尔位翻成 true"这种没有生产者的约定。
- **不强制**：正向段无门/入口/门槛类物件的开放场景（村道、田野、海面）。
- **门禁**：`scripts/check-assets.py` 第 ⑮ 项机械校验（带 `--selftest` 投毒对照）。

### A2·3 三条硬约束（实测踩出来的，缺一条就废）

1. **围合四面必填**：`N/E/S/W` 各声明 `wall_solid / wall_low / fence / house / door / window / open / edge_low / landmark / none`，**留空即违规**。实测：提示词只写了西墙，模型必把东墙也补上——**它补出来的东西看起来比你的空白更可信**，于是布局权威旁落给生图模型。
2. **外部地标方位钉死**：海／山／村道等主地标必须写"只在某向、远处、有水平线"，并明令其余三面不得出现。实测：不写时海会被画到东北角，且会像"地上一摊水"。
3. **基准图不携带时段**：允许柔和单侧光，但禁低角度长影／黄金暖调／逆光轮廓。基准图一旦锁死影子方向，下游每个机位都得跟着走，而本集不同时段戏份影子方向本就不同。**中性 = 不携带时段信息，不是没有光向。**

### A2·4 反增殖：提示词压不住，必须靠共识投票

实测同一条反增殖段把幻觉物件从 6 处压到 3 处，**压不到零**——补全没说的部分是这类模型的固有行为。因此定为硬规矩：

> **同一提示词出 3~4 张，取"共同出现的物件"为事实；只出现在一张里的判为幻觉。** 比对基准是 `space-truth.json` 的 `object_whitelist`，且判定必须是**物件集合相等**（多一个就报），不是"包含"（少一个才报）——多的那个比少的那个危险。

### A2·5 产出与派生

- 提示词**不得手写**：`python modules/scene-consistency/scripts/gen-layout-prompt.py --truth <space-truth.json> --fs-from-keyscene <key-scene.json> --out <项目>/outputs/xiatang/layout-prompts-空间基准图.md`
- 风格段由脚本**逐字**取合同「风格质感：」行，禁止手抄删减（实测手抄删掉后半段会让画风漂向写实）。
- 产物落 `<项目>/outputs/xiatang/layout-prompts-空间基准图.md`（**新文件名，勿覆盖 `asset-prompts.md`**）。
- `space-truth.json` 的 `approved != true` 时脚本拒绝出词（`--allow-unapproved` 仅用于草稿预览）。
- 门禁：`python modules/scene-consistency/scripts/check-space-truth.py --check <space-truth.json>`（八道，含 `--selftest` 投毒对照）。

### A2·6 分诊：什么病找哪张图

院子每集长得不一样／换机位灶跑了 → **A2**；窗开错墙／凭空多锚点／换景判错 → **空间真理图（文字）**；正反打左右互换／背对背／走进墙里 → **机位调度拓扑图**。
