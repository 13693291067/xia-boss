# battle-learner · 打戏学习官（改造版）

> **定位**：学习材料 → 提炼技法体系 → 产出 seedance-combat-prompt 格式的兵器/功法专项文件 → 回灌挂载副本。
> **与旧版（v2 fight-scene-director skills/battle-learner，已归档）的差异**：学习输入通道不变；**输出形态彻底改变**——不再写 learned 写法库（shot-grammar/rhythm/vfx-writing/prompt-pairs 四文件），改为产出**兵器技法资料库专项文件**；failures 失败案例不再单独成库，失败写法以「错误写法对照」形式吸收进专项文件的技法总原则/使用规则段。

## 一、触发与路由

- 用户说「学习打戏 / 打戏拉片 / 学习提示词 / 打戏提示词学习 / 入库学习 / 拉片学习 / 战斗学习库」→ 父 skill（xia-boss 根 SKILL.md §5）路由至本模块 → Read 本 SKILL.md 执行；
- 学习任务独立于分镜流水线（不依赖任何 Stage），学完回简报等用户确认；
- 学习任务不改变 xia-boss current 状态与 pipeline-state.json。

## 二、学习输入三通道（保留自旧版）

| 通道 | 输入 | 做什么 |
|---|---|---|
| A 提示词解剖 | 用户投喂的打戏提示词（一条或多条） | 拆解招式序列/动作因果/镜头语法/特效写法/节奏骨架 → 归纳出「体系」级技法（拳法/剑法/刀法/身法/法术体系皆可） |
| B 成片拉片 | 用户投喂的打戏成片视频 | **依赖 ffmpeg 抽帧**——环境未装时停下提示用户自备安装，**禁止自动下载**；逐帧摘动作节拍/接触点/运镜切换 → 反推技法体系与镜头建议 |
| C 配对对照 | 同一战斗的「提示词 + 成片」配对 | 双向对照：提示词哪句生成了什么画面、哪句崩了 → 崩法写进「错误写法」对照，稳定生成的好写法进技法表 |

**通用规则**：单次学习只产出**一个专项主题**（一套兵器/一门功法/一个体系）；材料不足以撑起一套体系（不足 12 招）时，如实向用户报告缺口并列出还需补充的材料类型，**禁止编招凑数**。

## 三、产出格式（★ 核心：七段式专项模板，与现有 6 份专项逐段对齐）

产出文件命名：`兵器技法资料库_{体系名}专项.md`，写入 **`modules/seedance-combat-prompt/` 根目录**（与 skill.md 同一目录层级——这是 weapons.md 声明的路径约定）。

## 四、登记回灌（挂载副本 weapons.md 更新）

新专项落盘后，**必须同步更新** `modules/seedance-combat-prompt/references/weapons.md`：

1. 「触发条件」清单追加一条（对齐既有条目句式）：`N. 创建{持有该体系的角色类型}，或用户明确绑定"{体系名}" → 读取 兵器技法资料库_{体系名}专项.md。`（并补"生成 XX 对战 / 用户要求 XX 细一点"类触发句）；
2. 「资料库路径」段追加：`兵器技法资料库_{体系名}专项.md`；
3. 「XX 定位速查」区追加该体系的速查表（对齐既有定位速查表列名：技法/核心风格/适合角色定位/兵器视觉签名/适合终结技类型）。

**注意**：挂载副本 `modules/seedance-combat-prompt/` 是唯一正本（学习产物只写这里）；技能库独立安装的 `seedance-combat-prompt` 是旧版快照，**不写、不同步**（用户 2026-09-07 拍板：挂载副本为正本）。对挂载副本的改动**仅限**：新增专项文件 + weapons.md 三处登记——SKILL.md 与其余 references 一律不动（原封不动原则）。

## 五、确认门控

1. 学习开始前：向用户复述材料主题、拟提炼的体系名、预计招式数，确认后再动手；
2. 专项文件产出后：全文给用户过目（重点：12 招命名、定位速查、错误写法对照），确认后落盘并登记 weapons.md；
3. 用户不满意时按其意见修订，**不允许带病入库**。
