# 角色状态依赖图与门禁（血缘·变异·换装·受伤·年龄 · 独立调度文件）

> 来源：前半程创作基准方法论蒸馏（★ 2026-09-03 集成）。**虾塘建立角色清单、产出任何角色提示词之前，加载本文件建立依赖图。** 目的：同一角色的多状态与血缘亲属按有向依赖管理，杜绝"下游图先出、上游没定稿"导致的连锁返工（下游脸/体型锚不到上游 = 整批重做）。

## 1. 必须登记为依赖的关系（有向）

| 类型 | 方向 | 例 |
|---|---|---|
| 血缘亲属 | 父母 → 子女/血亲 | 子女外貌同时依赖 2 名父母时，**两名都确认后才解锁** |
| 同一人状态 | 原形 → 换装/受伤/年龄/变异 | 换装身份、受伤后、老年版、变异形态 |
| 双胞胎/克隆 | 原形 → 复制体 | 唯一允许高度相似复制的关系 |
| 宿主与变身 | 宿主 → 变身形态 | 人形态 → 兽化态 |
| 绑定装甲/生物 | 着装者 → 装甲/共生体 | 脱甲态与着甲态 |
| 连续破损 | 前一状态 → 后一状态 | 完好的剑 → 崩口的剑（道具侧同构，见 prop-five-grid.md 状态轨迹） |

**依赖层通用化判断，不按剧本称谓写死**。典型顺序：`独立/父母/原始人形 → 子女或其他血亲 → 变异/受伤/换装/年龄状态`。

## 2. registry 字段契约（assets-registry.json）

```json
{
  "name": "角色B",
  "dependencies": {
    "type": "kin",
    "upstream": ["角色A", "角色C"],
    "relation": "血缘-子女",
    "note": "继承父母各1-2项家族特征"
  }
}
```

- `type`：`kin`（血缘）/ `state`（同一人换装/受伤/年龄/变异/变身/破损）——无依赖的基础角色**不写字段**。
- `upstream`：上游**角色资产名**（registry 内真实存在的名字）；状态类上游指向同一角色的基础主图。
- 变异多阶段逐阶段登记（如 `变异一期` / `变异终态` 各一条或以 identities 区分），**不得用最终形态污染早期形态**。
- 与既有机制兼容：kin/state 条目同样遵守原文锚定（闸门 1/2：chapter_range + evidence）与锁脸链；上游字段不替代原文证据。

## 3. 门禁规则（★ 强制）

1. **有上游依赖的角色/状态，只输出等待卡**（名称 + 依赖说明 + 所需上游清单）；上游未定稿前**不得写完整下游提示词**。
2. 上游"定稿" = 上游主图 image_ready 且通过资产图回传验证闸门（渲染介质与 style_tag 一致性核对）。
3. 同批次一次输出全部**同层无依赖**角色的提示词，供用户批量生成、逐张确认；整批确认后才解锁下一依赖层。
4. 用户上传图 ≠ 定稿——必须明确确认后才能解锁下游。
5. 删除/合并清单条目若会破坏依赖或关键身份识别，简短说明影响后由用户最终决定。

## 4. 继承规则（写下游提示词时执行）

- **血缘亲属**：引用上游定稿图（垫图锁脸），只继承 **2 至 4 项**稳定家族特征（如眉弓骨相/鼻梁/发色/体型倾向），并按年龄、性别和经历自然分化——**"像血亲但不是同一张脸"**。
- **同一人状态**（换装/受伤/年龄/变异）：最大限度保持原脸、身高和骨架，**只改剧情明确的部分**（服装/伤疤/白发/异化部位）；锁脸链不变（主图/原形定稿图作 ref）。
- **双胞胎/克隆**：才允许高度相似复制。
- 变异程度：剧本未明确时**只询问 1 次**——H1 人类主导（80%-90% 保持人类，局部牙齿/眼睛/指甲/手脚/耳部/体表异化）/ H2 均衡混合 / H3 野兽主导或完全兽化；剧本已明确则直接锁定并说明依据，不重复问。

## 5. 校验（check-assets.py 第 ⑧ 项）

- `upstream` 引用的名字必须存在于 registry characters（防依赖指向不存在的资产名）；
- 下游提示词已产出（prompt 非空）而上游主图/定妆提示词缺失 → 报错（违反门禁 1/2）。

## 6. 调度方式

| 时机 | 动作 |
|---|---|
| 建角色清单 | 全量扫描剧本，登记 dependencies（含人物小传中的资产依赖条目，来自虾料 production-facts） |
| 产出提示词前 | 按依赖分层；同层批量出词，跨层等待卡 |
| 逐层验收 | 整批确认后解锁下一层；全部层级确认后才进入角色设定板/关键道具收尾 |
